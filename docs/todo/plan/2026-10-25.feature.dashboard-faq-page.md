# Add an FAQ page to the dashboard

## Request
create http://fodo.test/faq with Frq Asked Questions:
- why use the ./docs/todo folder in each repo? (so todo list is saved with project, works really well together with CMS like mkdocs/mkdox)
- describe 'happy path'
- describe all possible /fodo:... commands in detail

## Analysis
Net-new page in the PHP dashboard (served by `/fodo:web` on 127.0.0.1:7787 and by `/fodo:valet` as
`http://fodo.<tld>`, so `fodo.test/faq` is the same route). The dashboard already routes on the URL
path in `index.php` (`$configView` for `/config`, `$agentsView` for `/agents`, around line 27), with
header links near line 935 and per-view crumbs ("← all repos"). A `/faq` view fits that pattern.

Content to cover:
- **Why `docs/todo/` in each repo**: the list lives and is versioned with the project (git history
  follows items via `git mv`), and it is plain markdown, so docs generators like MkDocs / mkdox render
  it alongside the rest of `docs/`.
- **Happy path**: `/fodo:add` → (optional `/fodo:plan n`) → `/fodo:start n|Pn` → `/fodo:done`,
  plus the side branches (skip, someday, wait).
- **Every command in detail**: add (incl. `--quick`, two-minute rule), list, show, plan, start,
  done, skip, someday, wait, busy (`--all`), repos (`prune`), init, web, valet; with the ID forms
  (`n`, `Pn`, `Bn`, `Sn`, filename, empty = current).

Open questions:
- Hard-code the FAQ as HTML in `index.php`, or keep it as a markdown file shipped with the plugin
  (e.g. `dashboard/faq.md`) and render it? The dashboard already renders markdown items, so a
  markdown source may be easier to keep in sync with the skills and README.
- The command descriptions duplicate `README.md` / `SKILL.md` descriptions; drift risk. Consider
  generating the command list from the `skills/*/SKILL.md` frontmatter descriptions at request time.

## Impacted files
- `plugins/fodo/dashboard/index.php` — `/faq` route, view rendering, header link to FAQ
- `plugins/fodo/dashboard/style.css` — styling for FAQ sections (headings, definition lists, code)
- `tests/web.bats` — test that `/faq` returns 200 and contains the key sections
- `plugins/fodo/README.md` — mention the FAQ page under the dashboard section
- (maybe) `plugins/fodo/dashboard/faq.md` — FAQ content source, if markdown is chosen

## Plan
1. Decide the content source (inline HTML vs. `faq.md` vs. generated from SKILL.md frontmatter).
2. Add `$faqView = rtrim($urlPath, '/') === '/faq';` and a view block like the `/config` one, with
   "← all repos" crumbs.
3. Write the three FAQ sections: why `docs/todo/`, happy path, command reference.
4. Add a "FAQ" link in the header next to Agents / settings.
5. Style it in `style.css` so it works in all four color schemes.
6. Add a bats test for `/faq`; mention the page in the README.

## Acceptance criteria
- `http://fodo.test/faq` (Valet) and `http://127.0.0.1:7787/faq` (`/fodo:web`) show the FAQ page.
- The page answers: why `docs/todo/` per repo (versioned with the project, MkDocs-friendly), the
  happy path, and every `/fodo:*` command with its arguments and ID forms.
- The header links to the FAQ; the page has the "← all repos" crumb.
- Readable in Light/Dark Colors and Monochrome schemes.
- `bats tests/web.bats` passes, including a new `/faq` test.
