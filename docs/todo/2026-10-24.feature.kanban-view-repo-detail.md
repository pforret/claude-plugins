# Add a read-only kanban view to the repo detail page

## Request
offer a kanban view when zoomed in on 1 project http://todolist.test/?repo=1
it's read-only, moving from backlog -> plan -> busy requires CLI access

in the kanban view, we don't need to see the filename in the card, just ID, created, type, size, confidence and title. add more info in mouseover

## Analysis
A new feature for the dashboard's repo detail page (`./?repo=<n>`). Today the page stacks one table per stage
(Busy, Plan, Backlog, plus Done/Skipped with `?all=1`), rendered by `render_table()` in
`plugins/fodo/dashboard/index.php` (~line 947). A kanban view shows the same items as cards in side-by-side columns
in lifecycle order: Backlog → Plan → Busy (→ Done → Skipped when `?all=1`).

Card content (decided by the user):
- **On the card:** ID badge (`3`, `P1`, `B1`), created date, type, size, confidence (only when set, i.e. plan items
  and items planned earlier) and title. **No filename** on the card.
- **On mouseover** (a `title` tooltip on the card, so no JS needed): the filename, the full title if the card
  shortens it, the stage dates that exist (`plan_at`, `busy_at`, `done_at`, `skipped_at`) and, for busy items, the last
  activity (`last_activity()` already builds such a "why" string). It could also show the first line of the item's
  `## Request`. That needs `items()` to read past the frontmatter, so it is optional and must stay cheap
  (stop reading at the first heading after `## Request`).

The view is read-only: no drag and drop, no POST, nothing written. Items move only through the CLI
(`/fodo:plan`, `/fodo:start`, `/fodo:done`). Cards can show the command that would move them
(e.g. `/fodo:plan 3`, `/fodo:start P1`, `/fodo:done B1`) as a hint or copy button. The ID in the hint must be
the positional ID shown on the same page, so it stays correct.

The URL in the request points at the personal `/todo` skill's dashboard (`todolist.test`). This repo's fodo
dashboard has the same `?repo=<n>` page, so this item targets the plugin; porting it to the personal copy is separate.

Open questions:
- Toggle between table and kanban (e.g. `?view=kanban`, remembered in localStorage like "show empty repos") versus
  kanban as the only layout.
- Default view: table or kanban.
- Are Done/Skipped columns only shown with `?all=1` (as now), and are they collapsed or capped (e.g. last 10)
  because they grow without bound?
- Next-step CLI command hint (`/fodo:start P1`): on the card, in the mouseover only, or not at all. The card should stay
  minimal, so the tooltip is the likely place.
- Narrow screens: columns scroll horizontally, or stack vertically.

## Impacted files
- `plugins/fodo/dashboard/index.php`: `render_kanban()` next to `render_table()`, view toggle, detail branch
- `plugins/fodo/dashboard/style.css`: column grid, cards, stage colours (all 4 schemes), mobile layout
- `tests/web.bats`: detail page renders kanban columns in order, with the right IDs; read-only (no form/POST)
- `plugins/fodo/README.md`: dashboard section mentions the kanban view

## Plan
1. Decide the open questions (`/todo <n> plan`).
2. Add `render_kanban(array $data, bool $showAll)` that renders one column per stage, reusing the stage labels and
   prefixes from `$stages` and the item fields `items()` already provides (title, type, size, confidence, busy_at, …).
   Add `plan_at` to `items()`. Card body = ID, created, type, size, confidence, title. The card's `title` attribute holds
   the filename, stage dates and (busy) last activity.
3. Add the view toggle to the detail page header and keep `?all=1` working with it.
4. CSS: columns via CSS grid (Backlog/Plan/Busy, plus Done/Skipped), cards matching `.card`/`mark.stage-*`,
   column headers with counts, dark/mono schemes, phone width.
5. bats test: fixture repo with one item per stage → kanban shows the columns in order and the IDs `1`, `P1`, `B1`;
   the card text has no filename, but the card's `title` attribute does; the page contains no `<form`.
6. README update; check visually in light and dark, desktop and phone.

## Acceptance criteria
- `./?repo=<n>` (in kanban mode) shows Backlog, Plan and Busy columns in that order, with counts; `?all=1` adds Done and Skipped
- Each card shows exactly: ID (same as the table view), created date, type, size, confidence (when set) and title (linked to the file); no filename
- Hovering a card shows a tooltip with the filename and the stage dates that exist (plus last activity for busy items), escaped with `e()`
- The view is read-only: no drag and drop, no forms, nothing written. If there are move hints, they are CLI commands with the correct IDs
- Works in all 4 colour schemes and at phone width without horizontal page scroll
- `bats tests/` and `php -l plugins/fodo/dashboard/index.php` pass
