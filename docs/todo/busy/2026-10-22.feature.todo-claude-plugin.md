# Package the todo skill and dashboard as the Claude Code plugin fodo

## Request
create a Claude Plugin that reproduces the functionality of the skill /Users/pforret/.claude/skills/todo
cf https://code.claude.com/docs/en/plugins/overview

- todo management in project folders and repos
- central todo dashboard like http://todolist.test/

## Analysis
Net-new deliverable: this repo (`ClaudePluginTodo`) currently holds only mkdocs scaffolding and
`docs/todo/`. The functionality already exists as a personal skill and a Valet site:

- `~/.claude/skills/work/SKILL.md` (renamed from `todo` to `work` on 2026-10-22 so `todo` is free
  for the plugin): one skill that dispatches list/init/add/plan/start/done/skip/show/busy/repos.
- `~/.claude/skills/work/work.sh` (was `todo.sh`, 362 lines): helper for folders, indexes, moves,
  frontmatter, `.current` and the global registry `~/.claude/todo/repos.csv`, plus a human CLI
  launcher layer (`work i|p|<id> …`, fzf picker, `exec claude "/work …"`).
- `~/.claude/skills/work/prp_template.md`: PRP sections appended by the plan verb.
- `~/.claude/todolist/` (`index.php` + `style.css` + icons + manifest): dashboard served by
  `valet link todolist` at `http://todolist.test`. It reads the registry and the markdown at request
  time. Verified on 2026-10-22: it also runs unchanged under `php -S 127.0.0.1:7787 -t .`
  (index 200, style.css 200, repo cards render).

The plugin keeps the data model byte-for-byte (`docs/todo/` layout, filenames, frontmatter, index
tables, registry CSV), so `/work` and the plugin can be used side by side on the same repos.

### Findings from the plugin docs and experiments (2026-10-22)
- Only `plugin.json` goes in `.claude-plugin/`. Components sit at the plugin root.
- **Plugin skills are always `/<plugin>:<skill>`.** This was tested with `claude -p --plugin-dir`:
  `/todosub:todo` and `/todoroot:todo` work, and a bare `/todoroot` does not, even with a root `SKILL.md`.
  So the commands are `/<plugin>:<verb>`, here `/fodo:<verb>`.
- `${CLAUDE_PLUGIN_ROOT}` **and** `$ARGUMENTS` are substituted in a plugin SKILL.md body. Tested:
  `ROOT=/…/exp/subskill ARGS=[1 plan]`. `CLAUDE_PLUGIN_ROOT` is *not* in the Bash tool env, so
  every command in a SKILL.md must spell out `"${CLAUDE_PLUGIN_ROOT}/scripts/todo.sh"`.
- `${CLAUDE_PLUGIN_ROOT}` = `~/.claude/plugins/cache/<marketplace>/<plugin>/<version>/` and changes
  on update. Old versions are deleted 14 days after an update. Never store state there.
- `claude plugin validate` additionally runs "plugin directory checks" that want a README.md
  (≥ 40 words), a LICENSE or `license` field, and a square PNG icon (512–2048 px) at
  `.claude-plugin/icon.png`.
- Names starting with `claude-` are reserved for plugins, and many names are reserved for
  marketplaces. `fodo` and `pforret-todo` are fine.
- The GitHub repo `git@github.com:pforret/ClaudePluginTodo.git` already exists (public), with one
  commit "Initial commit" containing an MIT `LICENSE`. The local repo has **no commits and no remote** yet.

## PRP

### Goal
A Claude Code plugin `fodo` in `plugins/fodo/`, published through the marketplace `pforret-todo` that
this repo provides (`pforret/ClaudePluginTodo` on GitHub). It reproduces the `/work` skill as eleven
verb skills, `/fodo:init|list|add|plan|start|done|skip|show|busy|repos|web`, backed by a bundled
helper script. It also ships the central dashboard, which `/fodo:web` serves with PHP's built-in
server. No shell command on the user's PATH: everything runs through Claude conversations.

### Why
- Makes the per-repo todo workflow (planned → plan/PRP → busy → done | skipped) installable and
  updatable for other people and other machines, instead of a hand-copied personal skill and Valet site.
- Keeps the exact on-disk format, so existing repos, the `/work` skill and the registry keep working.
- The dashboard no longer needs Valet. Anyone with `php` gets the cross-repo overview.

### Decisions taken
- Plugin skills can't be bare `/todo` → **one skill per verb**, `/fodo:<verb>` (user, round 1). Shared
  rules go in `reference/conventions.md`, which each skill tells Claude to read.
- Dashboard hosting → **`/fodo:web` runs `php -S`** on the plugin's `dashboard/` folder, not Valet (user, round 1).
- Shell access → **no shell CLI and no `bin/`**: "assume users will only use it through Claude
  conversations" (user, round 1). Drop the launcher layer (usage, fzf `cli_pick`, `run_claude`, `cli`, `cli_skip`).
- Publishing → **GitHub `pforret/ClaudePluginTodo`**, marketplace `pforret-todo`, plugin `fodo` (user,
  round 1). The repo already exists, with an MIT LICENSE commit (user message).
- Layout → **plugin in `plugins/fodo/`**, repo root = marketplace, so docs/mkdocs don't ship (user, round 2).
- Web server lifecycle → **detached `nohup php -S` + pidfile `~/.claude/todo/web.pid`**. It survives
  the session, is reused when already running and stops with `/fodo:web stop` (user, round 2).
- Auto-invocation → **all skills model-invocable** (no `disable-model-invocation`), same as `/work`
  today (user, round 2). Descriptions must therefore be precise and mention `docs/todo/`.
- License → **MIT** (user, round 2; matches `LICENSE` on origin/main).
- Registry → keep **`~/.claude/todo/repos.csv`** + `TODO_REGISTRY_DIR` (default, planner).
  `${CLAUDE_PLUGIN_DATA}` would be deleted on uninstall and isn't shared with `/work`.
- Port → default **7787**, overridable with `/fodo:web <port>` or `TODO_WEB_PORT` (default, planner;
  verified free and working on 2026-10-22).
- Version → `"version": "0.1.0"` in plugin.json, bumped per release (default, planner). Without a
  version every commit would count as an update.
- Plan → start handoff: the plan verb ends with `Plan ready (<n>/10). Start the implementation with
  "/fodo:start P<k>".` (default, planner).
- `/work` stays installed, so the plugin and the skill coexist on the same data (default, planner).
- Distribution → **both** our own marketplace `pforret-todo` **and** Anthropic's plugin directory
  (claude.ai/directory/manage → Plugin bundle → repo `pforret/ClaudePluginTodo`, plugin path
  `plugins/fodo`) (user message, 2026-10-22).
- Plugin name → **`fodo`** (user, round 4: wanted 4 fast-to-type letters). Rejected: `todo` (risks
  **Name is taken** or a generic-name hold), `prp-todo` (too long), `todo-md` (collides with the
  TODO.md format, todomd.org and a VS Code extension), `qodo` (Qodo, an AI coding company → brand
  hold), `yodo` (top GitHub repo of that name is a privilege-escalation exploit). The name is
  permanent after the first directory submission. Commands are `/fodo:<verb>`, displayName "Fodo".
  Data paths are unchanged: `docs/todo/`, `~/.claude/todo/`.
- Dashboard fonts → **system font stack, no Google Fonts** (user, round 3), so the dashboard makes
  zero external requests and the security scan has nothing undisclosed to flag.
- Supported surfaces → **Claude Code** (and Cowork sessions on the user's own computer). The plugin
  needs a local repo, bash, git and php, so claude.ai chat can't do anything useful with it. The
  README says so. The portal derives surfaces itself; we don't declare them (default, planner).

### Known gotchas & library quirks
- CRITICAL: every Bash invocation in a SKILL.md must be written with the literal
  `"${CLAUDE_PLUGIN_ROOT}/scripts/todo.sh"`. Claude Code substitutes it when the skill loads. Don't
  write `$CLAUDE_PLUGIN_ROOT` inside a shell snippet that expects the env var, and don't say
  "skill-dir". Quote it, because the path can contain spaces.
- CRITICAL: `set_field` in work.sh uses `sed -i ''`, which is BSD-only and breaks on Linux. Replace it
  with a temp-file rewrite (`sed -E … "$f" > "$f.tmp" && mv "$f.tmp" "$f"`). Also check the other
  sed/awk/find calls for GNU/BSD compatibility (they're POSIX today).
- The helper `cd`s to the git toplevel when `ROOT` is relative, so it runs from any subdirectory.
  Keep that, along with the `TODO_ROOT` and `TODO_REGISTRY_DIR` overrides (tests rely on both).
- `resolve()` is defined in the CLI layer of work.sh but used by `path` and `move`. Move it above
  when deleting the CLI layer. The fall-through `*)` dispatch branch becomes `usage` + exit 1 with a
  short list of the helper subcommands (no claude launching).
- `busy_all` warning text says `run 'work repos prune'`. Change it to `run /fodo:repos prune`.
  Index headings ("Todo — planned" …) stay identical so `/work` and the plugin produce identical files.
- Skill names are directories: `skills/start/SKILL.md` with `name: start` → `/fodo:start`. Use
  `argument-hint` in frontmatter (e.g. `<id>` or `[--all]`).
- `$ARGUMENTS` holds everything after the command. In each verb skill, treat an empty `$ARGUMENTS` as
  "current item" where `/work` did (done, skip, show).
- Because all skills are model-invocable, write descriptions that start with the action and mention
  `docs/todo/`, e.g. "Mark a docs/todo busy item done: verify acceptance criteria, write the Result
  section, archive it". Otherwise they will compete with the `/work` skill.
- `php -S` from Claude's Bash tool: start it with `nohup … >"$log" 2>&1 &` and write `$!` to the pidfile;
  the Bash tool must not wait on it. Check liveness with `kill -0 "$(cat pidfile)"`. Wait for readiness with
  `curl -s --retry 10 --retry-connrefused --retry-delay 1`, because an immediate curl returned 000 in testing.
- `php -S -t <dir>` serves `index.php` for `/` and static files directly. No router script is needed (verified).
- The dashboard links items with `file://` hrefs, which is fine locally. It must keep reading
  `TODO_REGISTRY_DIR`, so `web.sh` passes the variable through when it is set.
- `claude plugin validate` directory checks: README ≥ 40 words, LICENSE, `.claude-plugin/icon.png`
  square PNG 512–2048 px (icon-512.png is 512×512).
- Plugin name must not start with `claude-`. `fodo` is fine. A marketplace name equal to
  `<owner>-<repo>` of a different registered GitHub marketplace is refused. `pforret-todo` is fine.
- DIRECTORY (https://claude.com/docs/plugins/pre-submission-checklist), the rules that apply here:
  README ≥ 40 words *outside code blocks* in the plugin folder; LICENSE in the plugin folder; name
  lowercase/digits/hyphens; `description`, `author`, `version` set; **no `.DS_Store`/`Thumbs.db` in
  the plugin folder (Blocks)**; no symlinks/LFS; every non-image file < 256 KiB; ≤ 512 files; only
  text/SVG/PNG/JPEG/GIF/WebP/fonts (**no `.ico`**); don't refer to bundled images from scripts or in
  backticks/code blocks (web.sh serves the whole folder with `-t`, which is fine, but don't name
  `icon-512.png` etc. in scripts or code spans); valid YAML frontmatter with `description` as a single
  string in every SKILL.md; folder names on the path use only letters/digits/.-_ (`plugins/fodo` ok).
  "A script that SKILL.md only tells Claude to run isn't part of" the subfolder script-follow check,
  so our scripts don't trigger holds (no hooks, no MCP).
- SECURITY SCAN: the README must describe everything the plugin runs, writes and serves: bash helper
  in the repo's `docs/todo/`, `git mv`, registry `~/.claude/todo/repos.csv`, `php -S` bound to
  127.0.0.1 only, pid/log files in `~/.claude/todo/`, dashboard reading registered repos' `docs/todo`
  markdown, opening the browser. No network access. Keep source readable (no minification).
- Dashboard: remove the three `fonts.googleapis.com`/`fonts.gstatic.com` `<link>` tags from
  index.php, and in style.css set `font-family: Nunito, system-ui, -apple-system, "Segoe UI", Roboto,
  sans-serif` wherever Nunito is declared. Afterwards `grep -r googleapis plugins/fodo` must be empty.
- Add a root `.gitignore` with `.DS_Store`, `.idea/`, `site/`, and also `find plugins -name .DS_Store -delete`
  before validating. macOS creates them when you browse folders in Finder.
- Git: the local `main` has no commits. Attach to origin without losing the working tree:
  `git remote add origin git@github.com:pforret/ClaudePluginTodo.git && git fetch origin && git reset origin/main`
  (mixed reset; the working tree is untouched). Do **not** commit or push unless the user asks.
