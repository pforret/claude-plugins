# Keep plugin.json version in sync with VERSION.md

## Request
on https://claude.ai/directory/manage/plugins/3a0fd56a-4e8d-4e41-9022-3767f5d6261e?tab=versions
it always shows version 0.1.0
[Image #1: Versions tab listing `v0.1.0 · 6c5a426` (In review) and `v0.1.0 · 7ebf272` (Scan passed)]
does this always follow our @VERSION.md ?

## Analysis
No. The directory does not read `VERSION.md`; it reads `version` from
`plugins/fodo/.claude-plugin/plugin.json` at the pushed commit. The two files have drifted:

| commit | `VERSION.md` | `plugin.json` version | directory shows |
|--------|--------------|-----------------------|-----------------|
| 7ebf272 | 0.0.10 | 0.1.0 | v0.1.0 |
| 6c5a426 | 0.1.0 | 0.1.0 | v0.1.0 |

- `plugin.json` has said `"version": "0.1.0"` since the initial commit (9239c1f) and was never bumped.
- `setver` commits (`setver: set version to 0.0.5 … 0.1.0`) touch **only** `VERSION.md`
  (`git show --stat` on 6c5a426, f2b22d5, 2d5e5f9, 0899cf7).
- So every push so far shows up as v0.1.0, which makes versions indistinguishable in the portal and
  means Claude Code users of the marketplace never see an update (the client compares `plugin.json`
  versions).
- `DEVELOP.md:34` even says "Keep the version in `plugin.json` only", and `docs/publishing.md:8,78`
  says to bump `plugin.json`, contradicting the `setver`/`VERSION.md` habit.
- The web dashboard footer (`tests/web.bats:93`) also reads `plugin.json`.

Versioning is done with `setver` (`setver auto`, `setver new minor|patch|major`), so `VERSION.md`
is the source of truth. `setver` (`~/.basher/cellar/bin/setver`) only rewrites `VERSION.md`, a root
`composer.json` and a root `package.json`; it does not know `plugins/*/.claude-plugin/plugin.json`.
Open question: where to hook the copy `VERSION.md` → `plugin.json`: (a) extend setver with a
plugin.json step (upstream change, helps every plugin repo), (b) a git pre-commit hook in this repo,
(c) a tiny repo script run before `setver auto`, plus in all cases a test that fails when they differ.
Note the next bump must be > 0.1.0 (e.g. `setver new patch` → 0.1.1) or the directory shows 0.1.0 again.

## Impacted files
- `plugins/fodo/.claude-plugin/plugin.json` — the version the directory and Claude Code actually read
- `VERSION.md` — current `setver` target; keep, sync or remove
- `DEVELOP.md` — version-bump instructions must match the chosen approach
- `docs/publishing.md` — release steps (step 1 and "Updates") must match
- `tests/web.bats` (or a new bats test) — guard that `VERSION.md` == `plugin.json` version

## Plan
1. Keep `VERSION.md` + `setver` as the source; choose where the sync runs (setver / pre-commit / script).
2. Add the sync so `setver new …` / `setver auto` also rewrites `plugin.json` `version`.
3. Add a bats test asserting both versions are equal.
4. Update `DEVELOP.md` and `docs/publishing.md` to describe the single release step.
5. Bump to 0.1.1, push, and confirm the Versions tab shows v0.1.1.

## Acceptance criteria
- `VERSION.md` and `plugin.json` `version` are identical, enforced by a test
- `setver new <level>` / `setver auto` alone bumps the version the directory sees
- After the next push the directory Versions tab shows a version other than 0.1.0

## Notes
- Sync location chosen: a repo script `bin/release.sh`, not setver. `setver set|new` refuse a dirty
  tree and only stage files they know, so plugin.json could not join setver's version commit.
  The script bumps `VERSION.md` + every `plugins/*/.claude-plugin/plugin.json` in one commit
  (`release: set version to x.y.z`), tags `vx.y.z`, pushes commit + tag in one push (like `setver ap`).
- Guards: on `main`, clean tree, `main` == `origin/main`, new version > current, tag not taken.
  Runs shellcheck/php -l/bats/`claude plugin validate --strict` unless `--no-check`; `--dry-run` only prints.
- plugin.json is edited with awk on the top-level `"version"` line (jq would reformat the file).
- `tests/release.bats`: 5 tests incl. "VERSION.md matches every plugin.json version" for the real repo.
- Docs: `docs/publishing.md` release checklist and DEVELOP.md now point at `bin/release.sh`.
- Not yet released: the first real run (`bin/release.sh` → 0.1.1) is left to the user.
