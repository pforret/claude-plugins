# Improve the warnings in the Claude plugin directory review

## Request
bug
check if we can improve some of the warnings in the Claude Plugin review

(screenshot of the plugin directory review of fodo: Validation passed with 1 note; Directory policy "Held by directory policy" with findings REACH_UNKNOWN, MCP_FORWARDS_CREDENTIAL_ENV on .claude-plugin/plugin.json, UNKNOWN_KEY x4 on plugin.json (documentationUrl, privacyPolicyUrl, supportUrl, termsOfServiceUrl), RUNTIME_FETCH_EXEC on dashboard/index.php, USES_HOOKS; Security scan passed; Review "With a reviewer: Content policy review"; Publish waiting.)

## Analysis
The directory review of fodo is held for a human reviewer. Each finding, and what we can do about it:

- **REACH_UNKNOWN** ("couldn't confirm what the plugin runs or connects to", caused by a part of the
  plugin that couldn't be read cleanly, e.g. a skill's frontmatter). Every `skills/*/SKILL.md`
  description starts with `[this repo] ...` or `[all repos] ...`. In YAML an unquoted value that
  starts with `[` is parsed as a flow sequence, and `[this repo] Add a new item` is then invalid
  YAML. A strict parser fails on every skill frontmatter, which matches the finding. Claude Code's
  own loader is lenient, so the skills still work locally. Fix: quote the descriptions (or move the
  scope hint out of the leading position). Also quote `argument-hint: <n>` in plan/SKILL.md for
  consistency. This is the most likely root cause of the hold and clears "on the next push".
- **MCP_FORWARDS_CREDENTIAL_ENV** on `.claude-plugin/plugin.json`. The plugin ships no MCP server
  and plugin.json has no `env`, `mcpServers` or `${user_config...}` fields; the repo-root
  `.mcp.json` only points to a local PhpStorm server and is not part of the plugin. This looks like
  a scanner false positive that falls out of REACH_UNKNOWN (unreadable parts make the scanner
  conservative). Nothing to change; re-check after the frontmatter fix, else answer the reviewer.
- **UNKNOWN_KEY** x4 (documentationUrl, privacyPolicyUrl, supportUrl, termsOfServiceUrl). The
  message itself says these directory-listing fields are fine to keep. No action.
- **RUNTIME_FETCH_EXEC** on `dashboard/index.php`. The dashboard runs
  `proc_open([$bin, 'agents', '--json', '--all'])` where `$bin` comes from `FODO_CLAUDE_BIN` or the
  path stored in `~/.claude/todo/claude-bin` (written by `/fodo:valet`). The scanner sees "a path
  read at runtime, then executed" as download-and-run. Nothing is downloaded, but we can make that
  obvious: restrict `$bin` to a basename of `claude` (realpath, `basename === 'claude'`), prefer
  `which claude` / known install locations over the stored file, and add a comment block above
  `agents_cli()` stating that the binary is the user's own Claude Code CLI and no code is fetched.
  Mention the same in PRIVACY.md / README ("what the dashboard executes").
- **USES_HOOKS**: informational (SessionStart hook). No action.
- **Images and fonts passed without a code check** (icon.png): note only. No action.

Open question: whether the credential finding really disappears after the YAML fix; if not, the
reviewer note is the only remaining lever (the hold is "with a reviewer" anyway).

## Impacted files
- `plugins/fodo/skills/*/SKILL.md` (15 files): quote `description:` values that start with `[`, and `argument-hint: <n>`.
- `plugins/fodo/.claude-plugin/plugin.json`: no change needed; verify it stays valid JSON after any edit.
- `plugins/fodo/dashboard/index.php`: harden `stored_claude_bin()` / `agents_cli()` (basename check, explanatory comment).
- `plugins/fodo/README.md`, `plugins/fodo/PRIVACY.md`: one paragraph on what the dashboard executes.

## Plan
1. [x] In every `skills/*/SKILL.md`, wrap the `description:` value in double quotes (escape inner `"`), and quote `argument-hint: <n>`.
2. [x] Validate every frontmatter with a strict YAML parser (`python3 -c 'import yaml,sys; ...'` or `ruby -ryaml`) and `claude plugin validate` on `plugins/fodo`.
3. [x] In `dashboard/index.php`: in `stored_claude_bin()` accept the path only when `basename($bin) === 'claude'` and it is executable; add a doc comment above `agents_cli()` explaining the binary is the locally installed Claude Code CLI and nothing is fetched from the network.
4. [x] Add a short "What the dashboard runs" paragraph to README.md and PRIVACY.md.
5. [ ] Bump version, push, and compare the next directory review: REACH_UNKNOWN and the credential finding should be gone; RUNTIME_FETCH_EXEC may remain (it is a warning, not a hold). If the credential finding stays, reply to the reviewer with the analysis above.
