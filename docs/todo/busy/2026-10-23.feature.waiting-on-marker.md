# Add waiting_on marker for blocked busy items

## Request
GTD-inspired: a `waiting` marker for busy items (GTD's "Waiting for"), with a `waiting_on:` field such
as "PR #12 review", "upstream fix" or "client answer". The dashboard and `/fodo:busy` would show these
items separately, so blocked work doesn't look like active work.

## Analysis
A frontmatter field rather than a new folder: the item stays busy, so its `B<n>` ID and `.current`
logic are unchanged. `fodo.sh set <file> waiting_on "<text>"` already exists for writing it; clearing
needs an unset (or empty value) path. `/fodo:busy` output and the dashboard busy panel need to split
or mark waiting items (no spinner, show the reason). `/fodo:start` on a waiting item should clear it.

## Impacted files
- `plugins/fodo/scripts/fodo.sh`: `wait`, `resume`, `unset` commands; safe `set_field`; "Waiting on" column in the busy index; drop the fields when an item leaves busy
- `plugins/fodo/skills/wait/SKILL.md`: new `/fodo:wait [Bn] <reason>` / `/fodo:wait [Bn] resume` / bare `/fodo:wait`
- `plugins/fodo/skills/start/SKILL.md`: `/fodo:start Bn` on a waiting item resumes it
- `plugins/fodo/dashboard/index.php`: read the fields; waiting items styled, with reason, after active ones in "Busy — all repos"
- `plugins/fodo/dashboard/style.css`: `.waiting` styles, pause badge instead of the spinner
- `plugins/fodo/reference/conventions.md`: the fields and the helper commands
- `plugins/fodo/README.md`: command table, dashboard paragraph
- `tests/fodo.bats`, `tests/web.bats`: helper and dashboard tests

## Plan
See `### Implementation blueprint` in the PRP below.

## Acceptance criteria
- `/fodo:wait B1 PR #12 review` marks a busy item (`waiting_on`, `waiting_since`); `/fodo:wait B1 resume` clears it; non-busy items are refused.
- The busy table (`busy/index.md`, so `/fodo:busy` and `/fodo:list`) has a "Waiting on" column showing `⏸ <reason> (since <date>)`; B<n> numbering is unchanged.
- Moving an item out of busy (done, skipped) removes `waiting_on` and `waiting_since`.
- `/fodo:start B<n>` on a waiting item resumes it instead of being a no-op.
- Dashboard: waiting items show a pause badge (no spinner), muted, with the reason and since date, in the busy panel (sorted after active items), repo cards and kanban; reason text is HTML-escaped.
- Reasons with `|`, `&`, `/`, `\`, `#` and quotes are stored and shown intact (no sed breakage, no broken table).
- `shellcheck`, `php -l`, `bats tests/` and `claude plugin validate --strict plugins/fodo` pass.

## PRP

### Goal
A busy item can carry a "waiting for" marker with a free-text reason. It stays in `busy/` with its B<n> ID,
but every view (markdown busy table, `/fodo:busy`, dashboard) shows it as blocked, with the reason, and the
dashboard stops animating it as active work.

### Why
- GTD "Waiting for": blocked work (PR review, upstream fix, client answer) should not look like active work.
- Keeps the lifecycle unchanged (no new folder, IDs and `.current` untouched), like `someday/` kept its side branch small.
- The "Busy — all repos" panel becomes an honest view of what can be worked on right now.

### Decisions taken
- Markdown representation → one busy table with an extra "Waiting on" column, B<n> numbering untouched (user)
- Command → new `/fodo:wait` skill: `[Bn] <reason>` marks, `[Bn] resume` (alias `clear`) unmarks, bare lists (user)
- Dashboard → same places, distinct style: pause badge instead of spinner, muted, reason inline; waiting
  items sorted after active ones in "Busy — all repos" (user)
- Clearing → helper drops `waiting_on` + `waiting_since` when an item leaves busy; `waiting_since` is set
  automatically on mark (user)
- `/fodo:start B<n>` on a waiting item → resumes it (from the original analysis; otherwise still a no-op) (default)
- Storage → `waiting_on: "<reason>"` (double-quoted; `"` in the reason replaced by `'`, newlines by spaces),
  `waiting_since: yyyy-mm-dd` (default)
- Only busy items can wait → helper refuses others with a clear message (default)
- In repo cards and kanban, items keep filename order (IDs are positional); only the cross-repo busy panel
  re-sorts, its IDs are computed before sorting already (default)
- `set_field` rewritten with awk + ENVIRON so any value is safe and only the frontmatter is touched; fixes a
  latent bug where sed rewrote matching lines in the body too (default)
- Topbar "Busy N" count stays the total of busy items (default)

### Known gotchas & library quirks
- macOS ships BSD awk and BSD sed: no `sed -i` without suffix, no gawk-only functions. Use `awk` + temp file + `mv`, as the script already does.
- `field()` strips one pair of surrounding double quotes; PHP `frontmatter()` trims `"` and `'` at both ends. Store the reason double-quoted, and never with inner `"`.
- Markdown table cells: escape `|` as `\|` in the "Waiting on" cell (titles already go unescaped today; leave titles alone).
- The busy index is the only table with the new column; the other tables keep their exact format (other tests compare them).
- `mark.stage-busy:not(.topbar mark)::before` draws the spinner: the waiting rule must have higher specificity
  (`mark.stage-busy.waiting:not(.topbar mark)::before`) and also cover the reduced-motion rule.
- `set -euo pipefail` everywhere; `grep` with no match returns 1, guard with `|| true` where used in pipelines.
- shellcheck runs on the script in `bin/release.sh` checks; keep it clean.
