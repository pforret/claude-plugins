# Add quick capture mode to /fodo:add

## Request
GTD-inspired: a quick inbox mode, something like `/fodo:add --quick <text>` (or capturing several items
at once) that only writes the request text. Clarifying it then happens during `plan` or `review`.

## Analysis
GTD's Capture step should take no effort; today `/fodo:add` always researches the code to size and
plan the item. A quick mode writes only frontmatter (type guessed from the text, `size: unknown`)
plus `## Request`, and skips the code research. Multi-capture: several lines (or a pasted list)
become several items in one call. `/fodo:plan` and the planned review item must handle items with
empty Analysis/Plan sections. Check that `todo.sh` and the dashboard tolerate `size: unknown`.

## Impacted files
- `plugins/fodo/skills/add/SKILL.md`: `--quick` flag and multi-line capture
- `plugins/fodo/reference/item_template.md`: minimal variant for quick items
- `plugins/fodo/README.md`: document `--quick`

## Plan
1. Add `--quick` handling to the add skill: no code research, minimal template.
2. Support one item per line when several are given.
3. Make sure `/fodo:plan` fills in the missing sections; verify dashboard/list render `size: unknown`.
4. Update README.

## Acceptance criteria
- `/fodo:add --quick a\nb\nc` creates three minimal items without reading the codebase
- Quick items list and render normally, with size shown as unknown
- `/fodo:plan <n>` on a quick item fills in analysis, size, plan and criteria
