# Add waiting_on marker for blocked busy items

## Request
GTD-inspired: a `waiting` marker for busy items (GTD's "Waiting for"), with a `waiting_on:` field such
as "PR #12 review", "upstream fix" or "client answer". The dashboard and `/fodo:busy` would show these
items separately, so blocked work doesn't look like active work.

## Analysis
A frontmatter field rather than a new folder: the item stays busy, so its `B<n>` ID and `.current`
logic are unchanged. `todo.sh set <file> waiting_on "<text>"` already exists for writing it; clearing
needs an unset (or empty value) path. `/fodo:busy` output and the dashboard busy panel need to split
or mark waiting items (no spinner, show the reason). `/fodo:start` on a waiting item should clear it.

## Impacted files
- `plugins/fodo/skills/wait/SKILL.md`: new `/fodo:wait [Bn] <reason>` / `/fodo:wait [Bn] clear`
- `plugins/fodo/scripts/todo.sh`: show waiting state in `busy`/`list` output; unset support in `set`
- `plugins/fodo/dashboard/index.php`: render waiting items with their reason, no busy spinner
- `plugins/fodo/dashboard/style.css`: waiting style
- `plugins/fodo/reference/conventions.md`: document the field
- `plugins/fodo/README.md`: command table
- `tests/todo.bats`: busy output with a waiting item

## Plan
1. Define `waiting_on` (free text) and optional `waiting_since` date in conventions.
2. Add unset/clear to `todo.sh set`; mark waiting items in `busy` and the busy index table.
3. Write the `/fodo:wait` skill; have `/fodo:start` and `/fodo:done` clear the field.
4. Dashboard: separate or badge waiting items, show the reason.
5. README and tests.

## Acceptance criteria
- A busy item can be marked waiting with a reason and cleared again
- `/fodo:busy` and the dashboard show waiting items separately with the reason
- Waiting items don't get the "busy" spinner
- bats tests pass
