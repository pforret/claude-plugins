# After /fodo:commit bumps and tags, publish with checks and git push --follow-tags, not release.sh

## Context
The B1 PRP assumed bin/release.sh would see the tag created by /fodo:commit and stop at "tag v<new> already exists", leaving only the push. In practice release.sh derives the next version from VERSION.md, so after a /fodo:commit bump it would bump again.

## Options considered
- Make release.sh detect an already-tagged HEAD and only push: cleaner, but more release.sh logic and tests
- Document that after a /fodo:commit bump you run the checks and `git push --follow-tags`, without release.sh (chosen): no script change

## Decision
After /fodo:commit bumps and tags, publish with checks and git push --follow-tags, not release.sh

## Consequences
release.sh stays the path for releases without /fodo:commit. docs/publishing.md, the release.sh header comment, commit SKILL.md step 8 and the tag decision record all say this; keep them in sync if release.sh ever learns to skip an existing tag.
