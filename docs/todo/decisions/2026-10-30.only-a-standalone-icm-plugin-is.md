# Only a standalone icm plugin is weighed; folding ICM into fodo is out of scope

## Context
Planning the ICM investigation: which plugin shapes should the 'good Claude plugin' verdict weigh?

## Options considered
- Standalone `icm` plugin in this marketplace (skills such as /icm:init, /icm:setup, /icm:stage, /icm:status, /icm:lint): clean boundary with fodo. Chosen.
- Fold ICM-style staged workflows into fodo (stages as busy items, outputs as done items): avoids a second plugin but muddies fodo's scope. Rejected for this investigation.
- No plugin, clone the ICM repo as-is: remains a possible verdict of the investigation, not a shape to design.

## Decision
Only a standalone icm plugin is weighed; folding ICM into fodo is out of scope

## Consequences
The investigation designs at most one plugin shape. fodo's scope stays todo/PRP/decisions; any ICM support would be a separate plugin registered in .claude-plugin/marketplace.json.
