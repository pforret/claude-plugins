# The ID column pads the number to at least 2 characters so rows stay aligned from 9 to 10

## Context
While implementing the compact index tables, the user asked: "make the column always minimum 2 chars wide, so the table doesn't deform at item 9 -> item 10". In the raw index.md (GitHub source view, editors, `cat`) a row `| 9 |` and a row `| 10 |` have different widths.

## Options considered
- Pad the number with trailing spaces to 2 characters (`1 `, `P1 `, `P10`): aligned up to 99 items per table, IDs unchanged.
- Zero-pad (`01`, `P01`): aligned, but changes the IDs users type and `resolve` would need to accept both.
- No padding: rendered tables are fine, raw markdown shifts.

## Decision
The ID column pads the number to at least 2 characters so rows stay aligned from 9 to 10

## Consequences
Rows read `| 1  | 🐞 | …` and `| P1  | …`; tests and greps on index.md must allow the extra space (`| B1 | .*` patterns no longer match `| B1  |`). Renderers trim cell whitespace, so rendered tables are unchanged. Tables with 100+ items shift again at 99→100.
