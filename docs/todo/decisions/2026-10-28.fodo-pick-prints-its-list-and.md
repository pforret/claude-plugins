# fodo pick prints its list and prompts on stderr, only the result on stdout

## Context
The PRP for `fodo pick` said the numbered list and prompts go to stdout like `list`. But `pick_one` runs inside `rows=$(…)`-style command substitution in `pick`, so anything it prints to stdout is captured as the chosen row and never shown.

## Options considered
- stdout as in the PRP: needs `pick_one` to return the choice another way (global variable), more fragile.
- stderr for the list and prompts, stdout only for the chosen row / final line: what was done; the terminal shows both.

## Decision
fodo pick prints its list and prompts on stderr, only the result on stdout

## Consequences
The last stdout line of `fodo pick` is exactly `Run in Claude Code: /fodo:<cmd> <id>`, `cancelled` or `nothing to pick…`; tests match on it. Scripts piping `fodo pick` see only that line on stdout. Any new prompt in pick must go to stderr too.
