# ICM is judged as a docs/ convention for any repo, with this repo as the test case

## Context
Planning the ICM investigation: the request asks whether ICM "fits the docs/ subfolder for a repo's documentation". Does that mean this repo's docs/ or docs/ in general?

## Options considered
- Any repo, this repo as test case: evaluate ICM as a general convention a plugin or fodo could promote; use this repo's mkdocs docs/, docs/todo/ (fodo) and docs/agents/ (mkdokf) as the concrete check. Relevant to the plugin verdict.
- This repo only: narrower, says little about a plugin.

## Decision
ICM is judged as a docs/ convention for any repo, with this repo as the test case

## Consequences
The write-up must name the docs/ folder ICM would take in a generic repo and show it does not collide with docs/todo/ (fodo) or docs/agents/ (mkdokf). Only ICM Layer 3 (stable references) counts as documentation; Layers 1, 2 and 4 must be addressed explicitly.
