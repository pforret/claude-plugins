# /fodo:commit tags v<x.y.z> locally after a bump and never pushes

## Context
Planning /fodo:commit: `setver new` commits, tags and pushes commit and tags. How far should fodo go?

## Options considered
- Tag locally, never push: create `v<x.y.z>` after the bump commit; the user pushes with `git push --follow-tags` or bin/release.sh. Chosen; keeps PRIVACY.md's promise that fodo never pushes.
- Tag and push like setver: fully compatible, but a skill would publish to a remote.
- No tag, no push: versions in files and tags drift.

## Decision
/fodo:commit tags v<x.y.z> locally after a bump and never pushes

## Consequences
PRIVACY.md, README and conventions.md say: only /fodo:commit commits and tags, nothing in fodo pushes. After a /fodo:commit bump in this repo, run the checks and `git push --follow-tags` yourself; bin/release.sh computes the next version from VERSION.md, so running it on top would bump a second time (docs/publishing.md says so).
