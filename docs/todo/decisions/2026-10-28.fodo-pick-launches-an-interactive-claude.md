# fodo pick launches an interactive claude session, never claude -p

## Context
`fodo pick` hands the chosen item to a fodo skill, but planning and starting are Claude Code skills, not shell code. The request said to start `claude -p`; `-p` is headless print mode.

## Options considered
- `claude "/fodo:<cmd> <id>"` (interactive with an initial prompt): plan questions and permission prompts work; the user watches it run.
- `claude -p "/fodo:<cmd> <id>"` (headless): runs to the end and exits; `/fodo:plan` cannot ask its clarifying questions and `/fodo:start` would implement unattended or stall on permissions.
- Open plain `claude` and print the command to type: one extra step for the user.

## Decision
fodo pick launches an interactive claude session, never claude -p

## Consequences
`fodo pick` ends with `exec claude "<cmd>"` from the repo root, so it replaces the shell process. Never add `-p` here; a scripted or CI use would need a separate, explicit flag.
