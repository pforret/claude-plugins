# /fodo:commit updates an existing CHANGELOG.md but never creates one

## Context
Planning /fodo:commit: what does the skill do with CHANGELOG.md?

## Options considered
- Update an existing file only: no bump → entry under `## [Unreleased]` in its Keep a Changelog group (feat → Added, fix → Fixed, else Changed); bump → rename Unreleased to `## [x.y.z] - <date>`, add the entry, insert a fresh empty Unreleased. Never reorder or delete lines. Never create the file. Chosen.
- Also create the file when missing: overlaps with the planned /fodo:changelog skill (2026-10-30.feature.fodo-changelog-skill.md).
- Ignore CHANGELOG.md: the file goes stale after every commit.

## Decision
/fodo:commit updates an existing CHANGELOG.md but never creates one

## Consequences
/fodo:changelog owns creation and back-filling; /fodo:commit owns the per-commit entry. Both follow Keep a Changelog 1.1.0 and the same group mapping, so the two skills should share a reference file when /fodo:changelog is built.
