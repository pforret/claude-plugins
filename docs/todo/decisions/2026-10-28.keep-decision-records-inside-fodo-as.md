# Keep decision records inside fodo as /fodo:decide and docs/todo/decisions/, not a separate companion plugin

## Context
Looking for a companion plugin to fodo (docs/<subfolder> based, GTD and software-practice oriented), the strongest candidate was a decision/gotcha log: fodo tracks *what* is done, nothing tracks *why*. The question was whether that lives in its own plugin or inside fodo.

## Options considered
- Separate plugin (`fado`, `docs/decisions/`): clean scope, but it needs fodo's helper, the current busy item and the dashboard, so it would duplicate or depend on fodo.
- Inside fodo, `docs/todo/decisions/` beside the stage folders: reuses the helper, IDs, hook, review and dashboard; decisions are records, never moved, so the item lifecycle stays untouched.

## Decision
Keep decision records inside fodo as /fodo:decide and docs/todo/decisions/, not a separate companion plugin

## Consequences
Every fodo skill can record a decision through `fodo.sh decide`/`fodo.sh gotcha` without cross-plugin wiring. The plugin description and keywords must carry the trigger phrases, or `/fodo:decide` under-triggers. Supersede support (`--supersedes D<n>`) is a follow-up.
