# Drop the SessionStart command hook; the skills print the busy items and diff gotchas themselves, no CLAUDE.md line and no opt-in settings snippet

## Context
The plugin directory refuses every version that declares a hook of type command unless the publisher is a Verified organization (LOCAL_CODE_HOOK_COMMAND), and there is no way to apply. The hook was fodo's only proactive behaviour: busy items, decision count and the gotchas for files in the diff, printed at session start before the user types anything.

## Options considered
- A CLAUDE.md line written by /fodo:init that tells Claude to run the script at session start: close to the hook, but opt-in per repo and dependent on the plugin path
- An opt-in settings snippet in the README with today's hook: exact behaviour, almost nobody would paste it
- The skills print the busy items and matching gotchas themselves, in /fodo:list, /fodo:add and /fodo:start (chosen): covers the moments the user is in fodo, nothing automatic, nothing to configure

## Decision
Drop the SessionStart command hook; the skills print the busy items and diff gotchas themselves, no CLAUDE.md line and no opt-in settings snippet

## Consequences
hooks/hooks.json goes away and session-start.sh becomes `fodo.sh session`, called by the skills; tests/hooks.bats follows. Claude no longer knows about busy items or gotchas in a session where no fodo command runs; the README, FAQ, decide skill, decision template and the gotchas.md header must stop promising a SessionStart hook. Revisit if the directory ever accepts command hooks from this publisher.
