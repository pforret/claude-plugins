# ICM is investigated hands-on, by running its workspace-builder, not by desk research alone

## Context
Planning the ICM investigation (/fodo:plan): how deep should it go before a go/no-go on adopting ICM in docs/ and on building an icm plugin?

## Options considered
- Hands-on run: clone ICM, run `setup` and at least two workspace-builder stages on a throwaway domain in its own Claude Code session. Costs an hour or two, gives real evidence on token load and friction.
- Desk research only: read CONVENTIONS.md, the README and the workspaces. Fast, but the usability verdict stays a guess.

## Decision
ICM is investigated hands-on, by running its workspace-builder, not by desk research alone

## Consequences
The write-up must contain a hands-on log; the acceptance criteria check for it. The run happens in the scratchpad clone, never inside this repo. If no second interactive session is possible, the agent notes that and walks the stage contracts in the current session instead.
