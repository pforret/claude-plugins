# /fodo:commit writes the version into setver's file set plus every .claude-plugin/plugin.json

## Context
Planning /fodo:commit: which files carry the version and must be rewritten on a bump?

## Options considered
- setver's set plus plugin.json, written inline by a helper: VERSION.md, composer.json, package.json (+lock), .env.example VERSION=/APP_VERSION=, a root shell script's version= line, and every .claude-plugin/plugin.json and plugins/*/.claude-plugin/plugin.json. Chosen; this repo needs plugin.json (tests/release.bats asserts it equals VERSION.md).
- Delegate to `setver new` when installed: reuses tested code but setver pushes, does not know plugin.json and is rarely installed.
- VERSION.md and plugin.json only: minimal, other repos get nothing.

## Decision
/fodo:commit writes the version into setver's file set plus every .claude-plugin/plugin.json

## Consequences
New file types with a version (pyproject.toml, Cargo.toml) go into plugins/fodo/scripts/semver.sh with a bats test, never into the skill prompt. plugin.json is edited with release.sh's awk so only the version line changes.
