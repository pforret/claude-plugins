# The changelog is the root CHANGELOG.md only, also in a multi-plugin repo

## Context
Planning /fodo:changelog in a marketplace repo that holds several plugins; a per-plugin `plugins/<name>/CHANGELOG.md` would match what the plugin directory shows per plugin.

## Options considered
- Root plus per-plugin files on request (`--path`): flexible, but /fodo:commit step 6 would need the same path logic and two files could drift
- Root `CHANGELOG.md` only (chosen): the file /fodo:commit already updates, one place to read

## Decision
The changelog is the root CHANGELOG.md only, also in a multi-plugin repo

## Consequences
Both skills read and write the same root file; `/fodo:commit` keeps refusing to create it. Per-plugin history is recovered from the entry text, so entries in a multi-plugin repo should name the plugin. Revisit only if a plugin gets its own release cadence.
