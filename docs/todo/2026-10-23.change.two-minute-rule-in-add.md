# Offer to do trivial items immediately in /fodo:add

## Request
GTD-inspired: the two-minute rule in `/fodo:add`. When Claude sizes an item as trivial, it offers to do
it right away instead of filing it.

## Analysis
Pure skill-instruction change. "Trivial" needs a definition narrower than `small` (1–2 files), e.g.
a one-line or few-line change with no open questions. When the user accepts, the item should still
leave a trace: write it, move it straight to busy, implement, then run the done flow, so the archive
stays complete. Must ask rather than act, since `/fodo:add` is also triggered from plain-language
"note this for later" where the user explicitly wants it deferred.

## Impacted files
- `plugins/fodo/skills/add/SKILL.md`: new step after sizing: offer "do it now?" for trivial items
- `plugins/fodo/README.md`: mention the behaviour in the `/fodo:add` row

## Plan
1. Define "trivial" in the add skill.
2. After writing the item, if trivial and the user didn't say "for later", ask whether to do it now.
3. On yes: `fodo.sh move <n> busy`, implement, then follow the done skill.
4. Update README.

## Acceptance criteria
- Adding a trivial item prompts "do it now?"; non-trivial items don't
- Accepting ends with the item in `done/` with a Result section
- "add for later" phrasing never triggers the offer
