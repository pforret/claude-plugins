# Make the /fodo:list tables compact, one line per item

## Request
bug
the layout of /fodo:list is not great. the table layout is broken and not compact enough. The title and filename contains +- the same info. aim for 1 line per item. use emojis for type and size and add a legend.
[Image #1]

(Screenshot: `/fodo:list` in Claude Code with 7 planned items. The 6 columns `ID | Date | Type | Size | Title | File` do not fit the terminal width: "Size" wraps to "Siz/e", the date to "2026-10-2/3", "feature" to "featur/e"; titles wrap over 2–4 lines; the File column (long slug filenames) takes half the width and repeats the title; the table borders break out of alignment.)

## Analysis
A bug in the presentation: `/fodo:list` (and `/fodo:busy`, `fodo list`) prints the generated
`index.md` files verbatim (`list()` and `print_busy()` in `plugins/fodo/scripts/fodo.sh` just `cat`
them). Those tables come from `write_index()`: 6–7 columns, of which `Date` (already the filename
prefix), `Type` (spelled out) and `File` (a link whose slug repeats the title) waste most of the
width. Claude Code renders markdown tables with box borders and wraps cells when the table is wider
than the terminal, which breaks the layout seen in the screenshot.

Direction: drop `Date` and `File`, make the title the link to the file (`[title](file)`), show type
and size as emojis (e.g. 🐞 bug / 🔧 change / ✨ feature; size as S/M/L-style emoji such as 🟢 small /
🟡 medium / 🔴 large / ❔ unknown), and print a one-line legend under the tables. Target: `| ID | T |
S | Title |` (+ confidence for plan, waiting reason for busy), so a row fits on one line.

Open questions (all resolved in the PRP's Decisions taken):
- Change the `index.md` files themselves (also what GitHub/MkDocs show) or only the terminal output
  of `list`/`busy`? Changing `index.md` keeps one format and keeps "show verbatim" in the skills.
- Keep a date at all (useful for age), e.g. as `MM-DD` or relative ("5d")?
- Emoji choice and width: some emojis render double-width and may misalign plain-text columns;
  in markdown tables that is harmless.
- Legend: once at the end of `list` output, or in every `index.md`?
- `done/` and `skipped/` indexes (long lists): same compact format?

Tests depend on the current row format: about 20 assertions in `tests/fodo.bats` match
`| <ID> | <date> | …` and `tests/hooks.bats:74` greps `| B1 | .*First thing`. `fodo pick` reads
item files, not index.md, so it is unaffected; the dashboard reads item files too.

## Impacted files
- `plugins/fodo/scripts/fodo.sh` — `write_index()` compact columns, emoji maps, title as link, `|`/`]` escaping; `legend()` printed once by `list()` and `busy_cmd()`
- `tests/fodo.bats` — update the row/header assertions (lines ~46-47, 139, 244, 267, 344, 464-471); add tests for emojis, link, legend, escaping
- `tests/hooks.bats` — line 74 grep `| B1 | .*First thing` still matches; verify only
- `plugins/fodo/skills/list/SKILL.md`, `plugins/fodo/skills/busy/SKILL.md` — output (tables + legend) still shown verbatim; mention the legend
- `plugins/fodo/reference/conventions.md` — describe the index table columns and emoji legend

## PRP

### Goal
`/fodo:list`, `/fodo:busy`, `fodo list` and the generated `index.md` files show narrow tables, one
line per item in a ~100-column terminal: `| ID | T | S | Title |` with emoji type/size and the
title linking to the item file (plan: extra `Conf` column; busy: waiting reason inside the title
cell), followed once by a one-line emoji legend in the terminal output.

### Why
- The current 6-7 column tables wrap in Claude Code (screenshot in the Request) and are hard to read.
- Date and File repeat what the ID order and the title already say.
- One format for terminal, GitHub and MkDocs keeps the skills' "show index.md verbatim" rule.

### Decisions taken
- Where → change `index.md` itself via `write_index()`; the skills keep showing it verbatim (user, recommended). (recorded: decisions/2026-10-28.the-index-md-tables-themselves-use.md)
- Date column → dropped; order and IDs already follow the date, the linked filename carries it (user, recommended).
- Emojis → type 🐞 bug / 🔧 change / ✨ feature; size 🟢 small / 🟡 medium / 🔴 large / ❔ unknown or anything else (user, recommended). (recorded: decisions/2026-10-28.type-and-size-are-shown-as.md)
- Legend → printed once at the end of `list` / `busy` output, not in the index.md files (user, recommended). (recorded: decisions/2026-10-28.the-emoji-legend-is-printed-once.md)
- Tables covered → all item tables (planned, plan, busy, someday, done, skipped) share the format (default: one format, request says "the table layout"). (recorded: decisions/2026-10-28.all-item-tables-planned-plan-busy.md)
- Busy waiting reason → no separate column; appended to the title cell as ` ⏸ reason (since date)` (default: the column was empty for most rows).
- Decisions table → `| ID | Status | Title |` with linked title; Date, Item and File dropped (default: same problem, `/fodo:decide` shows it verbatim). (recorded: decisions/2026-10-28.the-decisions-table-is-compact-too.md)
- Header labels → `ID | T | S | Title` (+ `Conf` for plan) (default: shortest readable).

### Known gotchas & guardrails
- Mirror the existing patterns named under Context; do not introduce new ones for this item
- `write_index` writes with `echo` inside `{ … } > "$dir/index.md"`; keep the "_No <status> items._" line exactly (tests and skills match it).
- Titles are not escaped today; the waiting reason already is (`${wait//|/\\|}`). Escape `|` in titles the same way and `]` as `\]` because the title becomes link text.
- Link target stays the bare filename (`[title](<base>)`), relative to the index's own folder, as today.
- Type comes from the filename's 2nd segment (`cut -d. -f2`); unknown values map to ❔, never fail.
- macOS bash 3.2 + UTF-8 emojis: plain `case` mapping in a helper (`emoji_type`, `emoji_size`) is fine; no associative arrays.
- Legend text (one line, markdown italic like the other footer lines in list()):
  `_🐞 bug · 🔧 change · ✨ feature — 🟢 small · 🟡 medium · 🔴 large · ❔ not sized_`
  Print it only when at least one item table with rows was printed (empty repo: no legend).
- PRESERVE: IDs/prefixes, row order, file names, `resolve`/`nth` (they use item_files, not the index), `fodo pick`, `stale` output (its own table, out of scope), dashboard (reads item files).
- Also update: list/busy SKILL.md wording (tables + legend, verbatim), conventions.md (index table columns), and the docs/todo/*/index.md files of this repo get regenerated by `reindex` — that is expected.

### Approach
Change only `plugins/fodo/scripts/fodo.sh` code paths that render tables: add small `emoji_type`
and `emoji_size` mappers and a `md_cell` escaper, then rewrite the header/row `echo`s in
`write_index()` for the four modes (plain, confidence, waiting, decisions) to the compact columns.
Add a `legend` function and call it once at the end of `list()` and of `busy_cmd()` (covers both the
single-repo and `--all` paths) when an item table had rows. Then update the tests listed above to
the new rows and add new ones, and adjust the two skills and conventions.md. Finish with a
`fodo.sh reindex` in this repo and look at `docs/todo/*/index.md`.
