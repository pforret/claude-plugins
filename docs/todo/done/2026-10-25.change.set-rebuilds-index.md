# Make fodo.sh set rebuild the index

## Request
Make `fodo.sh set` rebuild the index itself, so the list never shows a stale size or confidence. (Follow-up from the quick-capture item's Discoveries.)

## Analysis
`fodo.sh set <file> <key> <value>` (dispatch at `plugins/fodo/scripts/fodo.sh:303`) only calls `set_field`. The
`index.md` tables show `size` and, for plan items, `confidence`, so after `set` the list stays stale until something
reindexes. The headless `/fodo:start` run hit this ("list showed the old size until I ran reindex"). The skills work
around it: plan step 6 runs `set … confidence` and then `reindex`, and the start skill now also reindexes after `set … size`.
Only the dispatch `set` case should reindex. The internal `set_field` calls in `move_file` (`:221-222`) and `retype`
(`:247`) already reindex afterwards, and reindexing inside `set_field` would make every move rebuild 3 times.
Once `set` reindexes, the extra `reindex` calls in the plan and start skills are redundant but harmless. Remove them
for clarity, or leave them in (decide while doing it; leaving them is safer).

## Impacted files
- `plugins/fodo/scripts/fodo.sh`: `set)` dispatch case calls `reindex` after `set_field`
- `tests/fodo.bats`: `set size` on a planned item → `index.md` shows the new size without a separate reindex

## Plan
1. Change the dispatch case to `set_field "$1" "$2" "$3" && reindex`.
2. Add a bats test next to "set adds a missing field after status…" (`tests/fodo.bats`): init, `item` with size small,
   `reindex`, `set <file> size large`, then `docs/todo/index.md` contains `| large |`.
3. Optionally update the usage line ("set/replace a frontmatter field and reindex").
4. `bats tests/` and `shellcheck plugins/fodo/scripts/*.sh`.

## Acceptance criteria
- After `fodo.sh set <file> size <x>` (or `confidence`), `fodo.sh list` shows the new value with no separate reindex
- `move`, `move-file` and `retype` still reindex exactly once
- `bats tests/` and `shellcheck plugins/fodo/scripts/*.sh` pass
