# Add an FAQ page to the dashboard

## Request
create http://fodo.test/faq with Frq Asked Questions:
- why use the ./docs/todo folder in each repo? (so todo list is saved with project, works really well together with CMS like mkdocs/mkdox)
- describe 'happy path'
- describe all possible /fodo:... commands in detail

## Analysis
Net-new page in the PHP dashboard (served by `/fodo:web` on 127.0.0.1:7787 and by `/fodo:valet` as
`http://fodo.<tld>`, so `fodo.test/faq` is the same route). The dashboard already routes on the URL
path in `index.php` (`$configView` for `/config`, `$agentsView` for `/agents`, around line 27), with
header links near line 935 and per-view crumbs ("← all repos"). A `/faq` view fits that pattern.

Content to cover:
- **Why `docs/todo/` in each repo**: the list lives and is versioned with the project (git history
  follows items via `git mv`), and it is plain markdown, so docs generators like MkDocs / mkdox render
  it alongside the rest of `docs/`.
- **Happy path**: `/fodo:add` → (optional `/fodo:plan n`) → `/fodo:start n|Pn` → `/fodo:done`,
  plus the side branches (skip, someday, wait).
- **Every command in detail**: add (incl. `--quick`, two-minute rule), list, show, plan, start,
  done, skip, someday, wait, busy (`--all`), repos (`prune`), init, web, valet; with the ID forms
  (`n`, `Pn`, `Bn`, `Sn`, filename, empty = current).

Open questions:
- Hard-code the FAQ as HTML in `index.php`, or keep it as a markdown file shipped with the plugin
  (e.g. `dashboard/faq.md`) and render it? The dashboard already renders markdown items, so a
  markdown source may be easier to keep in sync with the skills and README.
- The command descriptions duplicate `README.md` / `SKILL.md` descriptions; drift risk. Consider
  generating the command list from the `skills/*/SKILL.md` frontmatter descriptions at request time.

## PRP

### Goal
`/faq` on the dashboard (`http://fodo.test/faq`, `http://127.0.0.1:7787/faq`) shows a readable FAQ
page rendered from a hand-written `plugins/fodo/dashboard/faq.md`: why `docs/todo/` per repo, the
happy path, and every `/fodo:*` command explained in detail with arguments, ID forms and examples.
A `?` icon in the topbar links to it. `md_html()` gains real table rendering and optional heading
anchors so the FAQ can have a clickable table of contents.

### Why
- New users (and the author, months later) need one place that explains the workflow and every command.
- The dashboard is where people look at their todos; help belongs next to it.
- Table support also improves the kanban detail panels, whose items (PRPs, index tables) contain tables.

### Decisions taken
- Command reference → hand-written in `faq.md` (user). Drift guard: a bats test fails when a skill dir has no `/fodo:<name>` heading in `faq.md` (default).
- Prose → `plugins/fodo/dashboard/faq.md`, rendered by `md_html()` (user). Not copied into the mkdocs `docs/` site (default; out of scope).
- Tables → `md_html()` renders a `|`-block whose second row is a `|---|` separator as `<table>`; other `|` blocks stay `<pre>` (user + default for the fallback).
- Navigation → `?` icon link beside the settings gear, `title="FAQ"`, `aria-label="FAQ"`, `aria-current` on `/faq` (user).
- TOC → `md_html($md, anchors: true)` adds `id="<slug>"` to h4/h5 for the FAQ only (kanban panels keep `false`, so their repeated "Request" headings never create duplicate ids); `md_inline()` additionally allows `#slug` links (default).
- `/faq/` → 301 to `/faq`, like `/config` (default). The FAQ page has no meta refresh, like `/config` (default).

### Known gotchas & library quirks
- `php -S -t dashboard/` (scripts/web.sh) has no router: `/faq` falls back to index.php (as `/config` does), but `/faq.md` is served raw as a static file — harmless (public docs).
- Valet serves the same dir through a symlink; read the file as `__DIR__ . '/faq.md'` (like `dirname(__DIR__)` for plugin.json). Missing/unreadable file → show a notice in the card, not a PHP warning.
- md_html() escapes everything; keep that. Table cells go through md_inline(). Split rows on `|` but not on `\|`; trim the outer pipes. Separator row matches `/^\|?\s*:?-{3,}:?\s*(\|\s*:?-{3,}:?\s*)*\|?$/`.
- Heading slug: lowercase, non-alnum → `-`, trim `-`; `/fodo:add` → `fodo-add`. With anchors on, de-duplicate slugs (`-2`, `-3`).
- md_inline() link rule: allow `^https?://` and `^#[a-z0-9-]+$`; everything else stays text (keep the `javascript:` test passing).
- The topbar wraps to ~3 rows on phones; a second icon must not push it further — put `?` immediately before the gear, same size.
- Don't add the meta refresh on /faq (reading a long page that reloads every minute loses the scroll position).
- Everything in faq.md must match current behaviour (v0.1.5): verify each statement against the SKILL.md files.
