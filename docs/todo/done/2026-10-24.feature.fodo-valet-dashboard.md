# Add /fodo:valet to serve the dashboard as http://fodo.test

## Request
add the command /fodo valet that installs the web dashboard also as http://fodo.test using Laravel Valet, if it is installed

## Analysis
Net-new capability next to `/fodo:web` (PHP built-in server on 127.0.0.1:7787). Valet serves a
folder permanently through nginx + PHP-FPM, so the dashboard is always available at
`http://fodo.test` without starting a server. This replaces the old skill's `todolist.test`
(`valet link todolist` on `~/.claude/skills/todo/web/`), which goes away when the todo skill is removed.

Plugin skills are always namespaced, so the command is `/fodo:valet` (not `/fodo valet`).

Things that make this more than one `valet link` call:
- **The plugin path changes on every update.** Installed plugins live under
  `~/.claude/plugins/cache/<marketplace>/<plugin>/<version-hash>/`, so linking
  `${CLAUDE_PLUGIN_ROOT}/dashboard` directly breaks after the next update. Options: (a) link a
  stable path `~/.claude/todo/dashboard` that is a symlink to the current plugin's `dashboard/`, and
  refresh that symlink whenever a fodo command runs (or `/fodo:valet` is re-run); (b) copy the
  dashboard files to `~/.claude/todo/dashboard/` and re-copy on `/fodo:valet`; (c) link the
  versioned path and tell the user to re-run after updates.
- **`/agents` needs the `claude` binary.** Under PHP-FPM the PATH is not the user's shell PATH, so
  `claude agents --json --all` is "not found". Store the absolute path (`command -v claude` at
  link time) where index.php can read it, e.g. `~/.claude/todo/config.json` key `claude_bin`, used
  when `FODO_CLAUDE_BIN` is not set.
- **HOME under FPM**: index.php already falls back to `posix_getpwuid()`; Valet's FPM runs as the
  user, so `~/.claude/...` resolves. Verify.
- **Routing**: `/config` and `/agents` rely on unknown paths falling back to `index.php`; Valet's
  BasicValetDriver does that (as it did for `todolist.test`). Verify, including `/agents/` → 301.
- **Valet detection**: `command -v valet`; if missing, print how to install
  (https://laravel.com/docs/valet) and that `/fodo:web` works without it. macOS only (Valet Linux is
  a separate project; out of scope unless trivial).
- `valet link` writes a symlink in `~/.config/valet/Sites/` and needs no sudo; `valet links` /
  `valet secure` may prompt for sudo, so avoid them. Plain `http` as requested; `valet secure` optional.
- Name collision: if `fodo` is already linked to another folder, say so instead of overwriting.
- Also offer `unlink` (`valet unlink fodo`) and `status`.
- README/PRIVACY must disclose that fodo creates a Valet link and a symlink/copy in `~/.claude/todo/`.

Open questions for planning: stable-path strategy (a/b/c), whether to `valet secure` (https), where to
store the claude path, and whether to also unlink the old `todolist` site.

## PRP

### Goal
`/fodo:valet` makes the fodo dashboard permanently available at `http://fodo.<tld>` (normally
`http://fodo.test`) through Laravel Valet, without running `valet` or `sudo`: it writes the same
symlink `valet link` would, pointing at a stable path that fodo keeps aimed at the current plugin
version. `/fodo:valet status` reports, `/fodo:valet unlink` removes it. `/agents` works there because
the absolute `claude` path is stored for the dashboard.

### Why
- One bookmarkable URL that is always up, without `/fodo:web` after each reboot; replaces the old
  skill's `todolist.test` so the `todo` skill can be removed.
- Survives plugin updates (each version lives in its own cache folder).
- Works from inside Claude: every `valet` subcommand re-execs itself through `sudo`, which fails
  without a terminal.

### Decisions taken
- Command name → `/fodo:valet [unlink|status]` (plugin skills are always `plugin:skill`; default).
- Mechanism → write the symlink `$VALET_HOME/Sites/fodo` directly instead of calling `valet link`
  (default; `valet link` only does `symlinkAsUser($target, Sites/$name)` but the launcher wraps every
  command in `sudo`, which fails without a TTY). Verified 2026-10-24: a bare symlink in
  `~/.config/valet/Sites/` served `/`, `?all=1`, `/config`, `/agents`, `style.css` (200) and `/agents/` (301)
  on Valet 4.11.1 with no restart.
- Plugin updates → stable symlink `~/.claude/todo/dashboard` → `<plugin root>/dashboard`, re-pointed by
  every run of `todo.sh` and `web.sh` when that symlink exists (user).
- HTTPS → serve http only; print `valet secure fodo` for the user to run themselves (it needs sudo);
  `status` shows whether a certificate exists (user).
- Old `todolist` link → if `$VALET_HOME/Sites/todolist` points into `~/.claude/skills/todo`, report it;
  the skill asks the user and only then runs `valet.sh unlink-todolist` (user).
- `claude` binary for `/agents` → `/fodo:valet` writes `command -v claude` to `~/.claude/todo/claude-bin`;
  index.php order: `FODO_CLAUDE_BIN` env, then that file if it names an executable, then `'claude'` (user).
  Never stored in config.json, so the `/config` page cannot change which binary runs.
- Site name → fixed `fodo` (default; keeps status/unlink/refresh simple).
- TLD → read `tld` from `$VALET_HOME/config.json`, fallback `test` (default).
- Valet home → `$FODO_VALET_HOME`, else `~/.config/valet` if it exists, else `~/.valet` (Valet < 4) (default).

### Known gotchas & library quirks
- CRITICAL: never run `valet` (any subcommand re-execs via sudo → "a terminal is required"); only `command -v valet` to detect it.
- CRITICAL: the Sites dir must be in `paths` of `$VALET_HOME/config.json`, or Valet won't serve the link. If it is missing, don't edit Valet's config: print "run once in a terminal: `cd ~/.claude/todo/dashboard && valet link fodo`" and exit 1.
- Collision: `Sites/fodo` exists and is not a symlink to `$STATE/dashboard` → print where it points and exit 1. Never overwrite.
- Use `ln -sfn` for the stable link (re-pointing a symlink to a directory without -n creates a link inside it).
- Refresh in todo.sh/web.sh only if `$STATE/dashboard` already is a symlink (valet set up) and its target differs; silent; `|| true`. Developing with `--plugin-dir` re-points it to the working copy; acceptable, mention it in conventions.md.
- Parse config.json with `php -r` (Valet implies PHP): `php -r '$c=json_decode(file_get_contents($argv[1]),true); echo $c["tld"]??"test";' "$cfg"` and same for paths (one per line). Fallback tld `test` if php fails.
- https: certificate exists if `$VALET_HOME/Certificates/fodo.<tld>.crt` exists → status prints https URL.
- Old link check: `readlink "$SITES/todolist"` starts with `$HOME/.claude/skills/todo` → print a line starting `todolist:`; the skill turns that into a question.
- index.php: `is_file($f) && ($b = trim((string) file_get_contents($f))) !== '' && is_executable($b)`; still pass as one array element to proc_open (no shell).
- macOS `readlink` has no `-f`; only `readlink` (one level) is needed here.
- Keep the scanner-safe style: no `${x:-$y}` defaults, no `http://` strings in PHP (status/URLs are printed by bash only).
