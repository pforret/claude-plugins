# Directory policy failed: the SessionStart command hook is refused for non-Verified organizations

## Request
bug

Screenshot of the plugin directory's latest check: "Validation has warnings · Directory policy failed".

Needs you:
- Hooks of type command accepted only from Verified organizations. "The directory accepts command hooks only from Verified organizations, and your organization isn't one, so this version is refused. Remove every hook of type command, then push a new commit. Hooks of type prompt can stay." This plugin declares a hook of type command, which runs a command on the user's computer without asking. Anthropic chooses who is a Verified organization, and there's no way to ask to become one yet. (LOCAL_CODE_HOOK_COMMAND)

Other findings:
- Image or font file that the plugin's code could run (.claude-plugin/plugin.json): if nothing runs the file, leave it; the plugin stays held for review.
- Uses a credential from the user's machine (.claude-plugin/plugin.json): pass a ${user_config.KEY} value instead of reading the installer's credential, or remove every part that reads a credential.
- Unrecognized field in plugin.json (4 findings): check spelling against the plugins reference, otherwise it can stay.
- Field from another tool's manifest (.claude-plugin/plugin.json · icon): the directory reads 'icon'; Claude Code ignores it. No action needed.
- Contains a download-and-run command (dashboard/index.php): where the plugin runs this, ship the script inside the plugin; where it only appears in documentation, nothing to change.
- Uses hooks: listed for information only.
- Images and fonts passed without a code check: .claude-plugin/icon.png.

## Analysis
The one blocking finding is `hooks/hooks.json`: a `SessionStart` hook of `type: command` that runs
`scripts/session-start.sh` (busy items, decision count, gotchas for the files in the diff). The
directory refuses every version that declares a command hook unless the publisher is a Verified
organization, and there is no way to apply. So the hook has to go, or change type.

Ways out, to settle in `/fodo:plan`:
- **Drop the hook, keep the script.** `session-start.sh` stays as `fodo.sh`'s companion; the
  README tells users who want the reminder to add the hook themselves in their own
  `~/.claude/settings.json` (one JSON snippet, pointing at the installed plugin path). The plugin
  loses its "automatic" reminder but passes the policy. Simplest; every skill already starts with
  `fodo.sh` calls, so a `fodo.sh busy` at the top of `/fodo:list` and `/fodo:add` could partly
  replace it.
- **Replace it with a `type: prompt` hook.** The directory says prompt hooks can stay. A prompt
  hook on SessionStart cannot run a script, so it can only inject fixed text, something like
  "This repo may have docs/todo/busy/ items; run `fodo.sh busy` before planning". Check in the
  hooks reference whether SessionStart supports prompt hooks at all and what they can see (cwd?).
- **Keep the command hook and stay out of the directory**, installing via the marketplace only.
  The marketplace already works that way today; the directory listing is the thing at stake.

The other findings are warnings, not blockers (codes from the expanded check view):
- `UNREAD_ASSET_REFERENCED` (.claude-plugin/plugin.json): the `icon` field points at
  `.claude-plugin/icon.png`, which nothing runs. Leave it; the directory holds the version for a
  human look at the image, no change needed.
- `MCP_FORWARDS_CREDENTIAL_ENV` (.claude-plugin/plugin.json): the plugin declares no MCP server
  and plugin.json reads nothing, so this looks like a false positive. The only place that touches
  the environment is `dashboard/index.php` `agents_cli()`, which forwards an allowlist (HOME, PATH,
  TMPDIR, LANG, LC_ALL, CLAUDE_CONFIG_DIR) to a local `claude agents --json --all`, no tokens. Leave
  it for the reviewer; if it keeps blocking, drop CLAUDE_CONFIG_DIR from the allowlist or document
  the allowlist in PRIVACY.md.
- `UNKNOWN_KEY_CROSS_TOOL` (`icon`): no action, the directory itself reads it.
- "Unrecognized field" (4): among `displayName`, `documentationUrl`, `supportUrl`,
  `privacyPolicyUrl`, `termsOfServiceUrl`; check the plugin manifest reference and drop or rename
  the ones the directory does not read.
- `RUNTIME_FETCH_EXEC` (dashboard/index.php): the dashboard has no curl/wget/eval; the only
  external command is the `proc_open` of the local Claude CLI in `agents_cli()` (line ~697), whose
  binary path comes from `FODO_CLAUDE_BIN`, the /fodo:valet stored path, or the PATH. Nothing is
  downloaded, so per the finding text nothing needs to change; a comment already says so. If the
  reviewer insists, the configurable binary path is the part to constrain.
- `USES_HOOKS`: information only; goes away with the command hook.

Risks: the hook is what makes busy items and gotchas visible without asking; dropping it silently
degrades the workflow for every user. The tests in `tests/hooks.bats` assert the command hook and
exercise the script, so they change with whichever option is taken.
