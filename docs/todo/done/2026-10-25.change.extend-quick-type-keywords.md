# Extend the quick-capture type keywords

## Request
Extend the keyword guess with "fix", "typo", "export" and "show". (Follow-up from the quick-capture item's Discoveries.)

## Analysis
Quick capture guesses the type from keywords (`plugins/fodo/skills/add/SKILL.md`, the "Guess the type" bullet in
`## Quick capture`). The headless runs showed misses: "fix typo in footer" → change (should be bug) and "export to csv" /
"export all items to csv" → change (should be feature). Proposed additions:
- bug: `fix`, `typo`
- feature: `export`, `show`
`show` is ambiguous ("show the size on cards" is a feature, "the list doesn't show X" is a bug). The bug check runs
first, so "doesn't show" still lands on bug through "doesn't/does not work"-style wording only if that wording is
extended to "doesn't/does not <verb>". Consider rephrasing the bug rule to "doesn't/does not …" in general.
Wrong guesses stay correctable with `fodo.sh retype` during plan/start, so this is a convenience, not a correctness fix.
Pure skill-text change; no script or test changes.

## Impacted files
- `plugins/fodo/skills/add/SKILL.md`: keyword list in the quick-capture section

## Plan
1. Bug keywords += `fix`, `typo`; generalise "doesn't/does not work" to any "doesn't/does not …"; feature keywords += `export`, `show`.
   Keep the order: bug is checked first, then feature, otherwise change.
2. `claude plugin validate --strict plugins/fodo`.
3. Headless check (as in the quick-capture item): `claude -p $'/fodo:add\n- fix typo in footer\n- export to csv\n- show the size on cards\n- the list does not show sizes'`
   in a scratch repo with `TODO_REGISTRY_DIR` in scratch → bug, feature, feature, bug.

- Existing guesses are unchanged ("the login page crashes …" → bug, "add dark mode" → feature)
