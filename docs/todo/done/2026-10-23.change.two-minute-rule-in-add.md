# Offer to do trivial items immediately in /fodo:add

## Request
GTD-inspired: the two-minute rule in `/fodo:add`. When Claude sizes an item as trivial, it offers to do
it right away instead of filing it.

## Analysis
Pure skill-instruction change. "Trivial" needs a definition narrower than `small` (1–2 files), e.g.
a one-line or few-line change with no open questions. When the user accepts, the item should still
leave a trace: write it, move it straight to busy, implement, then run the done flow, so the archive
stays complete. Must ask rather than act, since `/fodo:add` is also triggered from plain-language
"note this for later" where the user explicitly wants it deferred.

## Impacted files
- `plugins/fodo/skills/add/SKILL.md`: new step after sizing: offer "do it now?" for trivial items
- `plugins/fodo/README.md`: mention the behaviour in the `/fodo:add` row

## Plan
See `### Implementation blueprint` in the PRP below (Tasks 1–3).

## Acceptance criteria
- Adding a trivial item prompts "do it now?"; non-trivial items don't
- Accepting ends with the item in `done/` with a Result section
- "add for later" phrasing never triggers the offer

## PRP

### Goal
`/fodo:add` applies the GTD two-minute rule. When the item it just wrote is **trivial** (one file, about 10 lines or
fewer, nothing to decide, no new test) and the user did not ask to defer it, Claude asks with AskUserQuestion:
**Do it now** / **Keep it filed**. "Do it now" moves the item to busy, implements it, then runs the full done flow
(verify, `## Result`, archive to `done/`) in the same turn. "Keep it filed" ends the add exactly as today.

### Why
- Tiny fixes cost more to file, list and start later than to do right away (GTD "two-minute rule").
- The archive stays complete: even an instant fix leaves an item in `done/` with a Result section.
- It only asks, never acts on its own, so "note this for later" keeps working as a pure capture.

### Decisions taken
- Definition of trivial → **all of**: size `small`, exactly **one** file to change, roughly **≤ 10 changed lines**,
  **no open question** in the Analysis, and **no new test** needed. (user)
- Finish → **auto-run the done flow** after implementing: verify, append `## Result`, `move-file … done`. Nothing is
  committed. If verification fails, stop with the item left in busy, as the done skill already prescribes. (user)
- Ask style → **AskUserQuestion** with two options, "Do it now (Recommended)" and "Keep it filed", asked after the
  item is written, reindexed and its number shown. (user)
- Deferral phrases that suppress the offer → "for later", "later", "note this", "remind me", "someday", "backlog",
  "don't do it now", or an explicit `--later`. Also suppressed when several items are added in one call. (default, Claude)
- Quick capture (planned item "Add quick capture mode to /fodo:add", not yet implemented) → when that lands, quick
  items are never offered, because they aren't sized. The add skill gets one line saying the offer needs the sizing step. (default, Claude)
- The size scale stays `small | medium | large`. No new `trivial` value, so `fodo.sh`, the indexes and the dashboard are untouched. (default, Claude)

### Known gotchas & library quirks
- Skills reference plugin files via `${CLAUDE_PLUGIN_ROOT}/…`. Use that form for start/done (`${CLAUDE_PLUGIN_ROOT}/skills/start/SKILL.md`).
- Move by **file path** (`fodo.sh move-file <path> busy`), not by number. The number shown in step 5 is positional and
  the user may have other items. `move-file` to busy also writes `.current`, so the done flow can use `fodo.sh path ""`.
- Step 5's "same title already exists → append instead" case: no offer then (the item isn't new).
- The done skill normally needs the user to call it. Here the user's "Do it now" click is that consent; say so in the step.
- If, while implementing, the change turns out bigger than trivial (a second file, a design question), stop, leave the
  item in busy with a `## Notes` line, and tell the user to continue with `/fodo:start`/`/fodo:done`. Don't silently grow scope.
- Frontmatter `description` in SKILL.md is how Claude triggers the skill. Keep "note this for later" in it and add the
  two-minute offer without changing the trigger phrases.

### Anti-patterns
- Don't act without the AskUserQuestion click, even for one-character fixes.
- Don't copy the start/done steps into the add skill. Reference them, so there's one source of truth.
- Don't add a `trivial` size or touch `fodo.sh`/the dashboard.
- Don't commit.
- Don't keep implementing when the item outgrows "trivial". Stop at busy.
