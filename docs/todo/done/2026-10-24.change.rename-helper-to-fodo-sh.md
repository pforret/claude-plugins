# Rename the helper script todo.sh to fodo.sh

## Request
rename plugins/fodo/scripts/todo.sh to fodo.sh in line with the branding

## Analysis
A change to existing naming: the plugin is branded "fodo" (commands `/fodo:*`, `scripts/web.sh`), but its
main helper is still called `todo.sh`, a leftover from the original `/todo` skill. There are about 109 references
in 17 files outside `docs/todo/`: every skill calls `bash "${CLAUDE_PLUGIN_ROOT}/scripts/todo.sh"`, and
`conventions.md` documents its subcommands. The script's own header and usage messages, both bats suites,
the new `valet.sh`, the plugin README and `docs/publishing.md` also mention it.

It is "large" only by file count. The change is mechanical: `git mv` plus a search-and-replace, with no
change in behaviour. The script is internal to the plugin, so no outside caller breaks. The personal
`~/.claude/skills/todo/todo.sh` skill is a separate copy and is not affected.

Scope boundaries (decided during planning, see PRP → Decisions taken):
- Out of scope unless decided otherwise: the registry folder `~/.claude/todo/`, the env vars
  `TODO_REGISTRY_DIR` / `TODO_WEB_PORT` and the `docs/todo/` layout. Renaming those breaks existing users' data
  and the compatibility with the `/todo` skill, so it would need a migration.
- Leave historical text untouched: items in `docs/todo/done/` and `docs/publishing.md`. Update the planned items that mention `todo.sh`,
  so later work uses the new name.
- The valet item (`valet.sh`, `skills/valet/`, `tests/valet.bats`) is finished, so its files are included in the rename.

## Impacted files
- `plugins/fodo/scripts/todo.sh` → `fodo.sh`: `git mv`; header comment and usage messages
- `plugins/fodo/scripts/valet.sh`: references to the helper
- `plugins/fodo/reference/conventions.md`: helper section and command list
- `plugins/fodo/skills/*/SKILL.md` (10 skills): the `bash "${CLAUDE_PLUGIN_ROOT}/scripts/todo.sh"` invocations
- `plugins/fodo/README.md`: "What this plugin runs and writes" names the helper
- `tests/todo.bats` (→ `tests/fodo.bats`?), `tests/valet.bats`: script path and expected usage messages
- `plugins/fodo/skills/valet/SKILL.md`: check for helper references
- planned items in `docs/todo/*.md` (top level only): mentions of `todo.sh`

## PRP

### Goal
The fodo plugin's helper script is `plugins/fodo/scripts/fodo.sh` (renamed with `git mv`, history kept), its test suite
is `tests/fodo.bats`, and every skill, the reference docs, the README, the other scripts/tests and the planned todo
items refer to `fodo.sh`. Behaviour is identical; only names and messages change.

### Why
- Consistent branding: commands are `/fodo:*`, the dashboard and docs say fodo; `todo.sh` is a leftover of the `/todo` skill.
- Avoids confusion with the separate personal `/todo` skill, whose own helper is also called `todo.sh`.

### Decisions taken
- Timing → do it now and include the valet files; the valet item is finished (user).
- Test file → `git mv tests/todo.bats tests/fodo.bats` (user).
- Other text → update the planned items in `docs/todo/*.md`; leave `docs/todo/done/` and `docs/publishing.md` (history) as they are (user).
- `docs/todo/busy/` and `docs/todo/plan/` items → left alone: they are this item and the valet item, whose text describes their own work at the time (default).
- No `todo.sh` compatibility shim: the scripts and skills ship together in one plugin version, so nothing outside calls the old path (default).
- Out of scope: `~/.claude/todo/`, `TODO_REGISTRY_DIR`, `TODO_WEB_PORT`, `docs/todo/` layout, and the personal `~/.claude/skills/todo/` skill (default; renaming those breaks data/compatibility).

### Known gotchas & library quirks
- CRITICAL: `valet.sh`, `skills/valet/` and `tests/valet.bats` are untracked (not yet committed). `git mv` only applies to the two
  tracked files; just edit the untracked ones in place. Don't `git add` or commit anything.
- `todo.sh` is tracked but has uncommitted edits: `git mv` keeps them (it moves the working-tree file).
- Replace the token `todo.sh` only; don't touch `todo/` paths, `TODO_*` env vars, `docs/todo`, `/todo` or `todo.bats` (that one is a
  rename, handled by git mv; then fix any text reference to `todo.bats`).
- On macOS use `sed -i ''` (BSD sed); or a small python/perl one-liner to stay portable.
- Watch the word boundary: also matches `scripts/todo.sh"` inside quotes, which is wanted.
- `docs/todo/*.md` top level only (planned items), via `todo.sh` → `fodo.sh` there too; then run the personal helper's
  `reindex` (`bash ~/.claude/skills/todo/todo.sh reindex`). That's the /todo skill's own helper, which must NOT be renamed.
