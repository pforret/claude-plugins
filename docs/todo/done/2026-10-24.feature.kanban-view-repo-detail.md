# Add a read-only kanban view to the repo detail page

## Request
offer a kanban view when zoomed in on 1 project http://todolist.test/?repo=1
it's read-only, moving from backlog -> plan -> busy requires CLI access

in the kanban view, we don't need to see the filename in the card, just ID, created, type, size, confidence and title. add more info in mouseover

## Analysis
A new feature for the dashboard's repo detail page (`./?repo=<n>`). Today the page stacks one table per stage
(Busy, Plan, Backlog, plus Done/Skipped with `?all=1`), rendered by `render_table()` in
`plugins/fodo/dashboard/index.php` (~line 947). A kanban view shows the same items as cards in side-by-side columns
in lifecycle order: Backlog → Plan → Busy (→ Done → Skipped when `?all=1`).

Card content (decided by the user):
- **On the card:** ID badge (`3`, `P1`, `B1`), created date, type, size, confidence (only when set, i.e. plan items
  and items planned earlier) and title. **No filename** on the card.
- **On mouseover** (a `title` tooltip on the card, so no JS needed): the filename, the full title if the card
  shortens it, the stage dates that exist (`plan_at`, `busy_at`, `done_at`, `skipped_at`) and, for busy items, the last
  activity (`last_activity()` already builds such a "why" string). It could also show the first line of the item's
  `## Request`. That needs `items()` to read past the frontmatter, so it is optional and must stay cheap
  (stop reading at the first heading after `## Request`).

The view is read-only: no drag and drop, no POST, nothing written. Items move only through the CLI
(`/fodo:plan`, `/fodo:start`, `/fodo:done`). Cards can show the command that would move them
(e.g. `/fodo:plan 3`, `/fodo:start P1`, `/fodo:done B1`) as a hint or copy button. The ID in the hint must be
the positional ID shown on the same page, so it stays correct.

The URL in the request points at the personal `/todo` skill's dashboard (`todolist.test`). This repo's fodo
dashboard has the same `?repo=<n>` page, so this item targets the plugin; porting it to the personal copy is separate.

The open questions (toggle/default, Done/Skipped growth, move hint, narrow screens) were resolved during planning.
See `### Decisions taken` in the PRP below.

## PRP

### Goal
`./?repo=<n>` on the fodo dashboard shows the repo's items as a **read-only kanban board** by default: columns
Backlog → Plan → Busy (→ Done → Skipped with `?all=1`), each with a count, one compact card per item. A
"Table view" / "Kanban view" link switches to the existing tables (`?view=table`) and back. Nothing is draggable or
writable; each card's tooltip says which `/fodo:` command moves it on.

### Why
- One look at a repo shows the flow of work (what's waiting, planned, in progress) instead of three stacked tables.
- Reuses the data the detail page already loads (`$detail['data']`), so no new file reads beyond a cheap peek at `## Request`.
- Keeps the dashboard's rule: it never writes to repos. Moves stay on the CLI, and the tooltip names the exact command.

### Decisions taken
- Table vs kanban → **toggle, kanban is the default**. `?view=table` selects the tables, anything else (or nothing) is kanban.
  Carried in the URL, so the 60 s meta refresh and `?all=1` keep it. No JS, no localStorage. (user)
- Done/Skipped growth → **cap at the 10 most recent** per column (by filename = date, newest first). The column header
  shows the full count, and a footer line says `+N older, see table view` linking to `?view=table&all=1`. (user)
- Move hint → **tooltip only**: last tooltip line `next: /fodo:plan 3 or /fodo:start 3` (backlog),
  `next: /fodo:start P1` (plan), `next: /fodo:done B1` (busy). Done and skipped get no hint. (user)
- Narrow screens → **stack vertically** below 700px (same breakpoint as `table.detail`). No horizontal scroll. (user)
- First line of `## Request` in the tooltip → **yes**, via a new cheap `request_peek()` that stops at the next heading
  and is capped at 200 chars. Only called for kanban cards, not on the overview. (default, Claude)
- Card title → full title, wrapping, linked to `file://<path>` like `render_table()`. No `short()`, so the tooltip
  doesn't have to repeat the title. (default, Claude)
- Scope → the fodo plugin dashboard only. Porting to `~/.claude/skills/todo/web/index.php` is separate. (from the Analysis)

### Known gotchas & library quirks
- `declare(strict_types=1)` is on. Cast ints before passing them to string functions (`(string) $n`).
- IDs are **positional per stage, 1-based, in filename order**. With the done/skipped cap, compute the ID from the
  original index BEFORE slicing/reversing (`$n = $i + 1` over the full list, then take the last 10 and reverse).
- Backlog IDs have no prefix (`3`), done/skipped have none either. Only plan = `P`, busy = `B`. Prefix 'B' gets the spinner via `mark.stage-busy`, which works automatically.
- Everything from item files is untrusted: titles, Request text and filenames go through `e()`. Never echo raw.
- `request_peek()` must not read whole files. Read line by line, stop at the first `## ` heading after `## Request`
  or after 60 lines, and return `''` when there is no Request section. Collapse whitespace and cap with `short($s, 200)`.
- Read-only: no `<form>`, no `draggable`, no `method="post"` anywhere in the detail page. The test asserts this.
- The page has `<meta http-equiv="refresh" content="60">`. The view must live in the URL (it does), or the refresh drops it.
- `$_GET['view']` is user input: compare with `=== 'table'`, never echo it.
- Keep `render_table()` and the table branch byte-for-byte compatible. `?view=table` must render exactly what the page rendered before this change.

### Anti-patterns
- Don't add drag and drop, buttons that look like they move items, or any POST. This view is read-only.
- Don't recompute IDs differently from `render_table()`. Hints with the wrong ID are worse than no hints.
- Don't read whole item files for the tooltip. `request_peek()` stops early.
- Don't hardcode colours. Use the stage tokens so all 4 schemes work.
- Don't add JS or localStorage for the toggle. The URL carries it.
- Don't change the overview (`./`) or `render_list()`/`render_card()`.
