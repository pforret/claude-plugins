# Add a web counterpart of Claude Code agent view to the dashboard

## Request
can we make a web counterpart for the Claude Agent View
https://code.claude.com/docs/en/agent-view

## Analysis
Agent view (`claude agents`) is a terminal screen that lists every Claude Code session on the machine,
grouped by state (Pinned, Ready for review, Needs input, Working, Completed) or by directory. Each row
shows name, a one-line summary and age; a peek panel shows detail. The dashboard already shows
"agent working/idle" badges per repo (from `~/.claude/sessions/<pid>.json`); this item adds a
read-only `/agents` page that lists the sessions themselves, fed by `claude agents --json --all`,
with a server-rendered peek panel showing the session's AI title, last prompt and last reply, read
from the tail of its transcript. Scope, data source, peek content and placement were decided during
planning (see PRP → Decisions taken).

## Impacted files
- `plugins/fodo/dashboard/index.php`: `/agents` route, CLI collector, transcript peek, state grouping, repo matching, nav link
- `plugins/fodo/dashboard/style.css`: agents list, state colors/icons, peek panel

## Acceptance criteria
- `http://127.0.0.1:<port>/agents` lists every session that `claude agents --json --all` returns, with name, repo, kind, state and age
- Sessions are grouped by state (Needs input, Working, Idle, Completed) with counts; `?by=repo` groups them by repo
- Blocked sessions show what they are waiting for (`waitingFor`)
- A session inside a registered repo links to that repo's detail page and shows its current busy item, if any
- `/agents?s=<sessionId>` shows a peek panel: AI title, last prompt, last assistant text reply, session id, cwd, and a copyable `claude attach <id|name>` command
- The page shows an explanatory notice (no PHP error) when `claude` is not found, fails, times out or returns invalid JSON, and an empty state when there are no sessions
- The PHP code never builds a shell string: the CLI runs via `proc_open` with an argument array and a timeout; `s=` is validated as a UUID before any file lookup
- The top bar links to `/agents`; agent badges on the overview link to `/agents`
- README and PRIVACY describe the command that is run and the transcript data that is read
- `bats tests/`, `shellcheck plugins/fodo/scripts/*.sh`, `php -l plugins/fodo/dashboard/index.php` and `claude plugin validate --strict plugins/fodo` pass

## PRP

### Goal
The fodo dashboard gets a read-only `/agents` page that mirrors `claude agents`: every Claude Code
session on this machine, grouped by state (or by repo), each row showing state icon, name, repo
(linked to its fodo card), the repo's current busy item, kind, `waitingFor` and age. Clicking a row
opens `/agents?s=<sessionId>` with a peek panel showing the session's AI title, last prompt and last
assistant reply. The page runs exactly one command, `claude agents --json --all`, with no shell,
and executes nothing else.

### Why
- One browser tab shows both the todo pipeline and what every agent is doing, across repos.
- Connects sessions to fodo items: "session X in repo Y is working on B1 <title>".
- Works without a terminal and next to the existing overview, without changing it.

### Decisions taken
- Scope → read-only (list, group, peek, copy `claude attach`); no stop/reply/dispatch (user).
- Data source → `claude agents --json --all`, the supported interface; no fallback to `sessions/*.json` on this page (user). The overview's existing badges keep using `sessions/*.json`, unchanged.
- Peek content → AI title + last prompt + last assistant text reply from the transcript tail (user).
- Placement → new `/agents` page, linked from the top bar and the agent badges (user).
- Peek mechanism → server-rendered via `?s=<sessionId>` rather than a JS drawer, so the page's meta refresh keeps the panel open (default; matches the dashboard's no-JS-fetch style).
- Refresh → `<meta http-equiv="refresh" content="15">` on `/agents` only (default; agent states change faster than todo items; overview stays at 60s).
- CLI binary → `getenv('FODO_CLAUDE_BIN') ?: 'claude'` resolved via PATH by `proc_open`; `FODO_CLAUDE_BIN` exists for tests and unusual installs (default).
- Timeout → 5 s; on timeout terminate the process and show the "could not list sessions" notice (default).
- State grouping (default), first match wins:
  `needs input` = `state` is `blocked` or `status` is `waiting`;
  `working` = `state` is `working` or `status` is `busy`;
  `completed` = `state` is `done`, `failed` or `stopped`;
  `idle` = everything else. Within `completed` keep the sub-state (done/failed/stopped) as the icon colour.
- Group order: Needs input, Working, Idle, Completed (agent view puts Pinned / Ready for review first; pins and PR data are not in the JSON, so they are left out).
- Attach command → `claude attach <id>` when `id` is present (background sessions), else `claude attach <name>`; interactive sessions get the hint "running in a terminal" instead, since they cannot be attached.
- Size → medium (6 files), down from large, because actions are out of scope.

```json
{"type":"assistant","message":{"role":"assistant","content":[{"type":"text","text":"…"},{"type":"tool_use",…}]},"timestamp":"…"}
```
Take the LAST occurrence of each within the final 512 KB of the file.

### Known gotchas & library quirks
- CRITICAL: never pass user input to the command; the argument array is fixed: `[$bin, 'agents', '--json', '--all']`.
- CRITICAL: `?s=` must match `/^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/` before it is used in `glob()`; otherwise ignore it (show the list without a peek) — no path traversal.
- The peek must only open transcripts of sessions that the CLI just listed (look the sessionId up in the parsed list); don't open arbitrary uuids.
- `proc_open` with an array resolves the binary via PATH; if it is missing, `proc_open` returns false or the process exits 127 with stderr — both must end in the notice, never a PHP warning on the page (use `@` or check return values; the dashboard runs with display_errors on in php -S).
- php -S is single-threaded: keep the timeout short (5 s) so a hung CLI can't block the server long.
- `$urlPath` routing: mirror `/config`: `rtrim($urlPath, '/') === '/agents'`, redirect `/agents/` → `/agents` like config does.
- The existing early-return blocks (`?icon=`, `/config` POST) run before the HTML; put the agents data collection after `$blocks` is built (repo matching needs it) and before `?>`.
- Repo matching: factor the longest-prefix loop (~486-491) into `repo_for_cwd(array $blocks, string $cwd): ?array` and use it in both places; behaviour of the overview must not change.
- Current busy item of a repo: read `<repo>/docs/todo/.current` (a filename); if it exists in `busy/`, show its frontmatter title and `B<n>` (position in `$b['data']['busy']`). Else, if exactly one busy item, show that one. Else nothing.
- Transcript text may contain anything: always `e()` it; truncate prompt/reply to ~2000 chars for display; render in `<pre class="peek-text">` with `white-space:pre-wrap`.
- Line-by-line json_decode of a 512 KB tail: skip the first (partial) line; ignore decode failures.
- Colour schemes: the monochrome schemes override stage colours; use the existing tokens (`--busy`, `--warning`, `--success`, `--error-text`, `--zinc-400`) so all 4 schemes work, and respect `prefers-reduced-motion` for the working pulse (reuse `.agent.working i` animation).
- No external requests: the existing bats test greps for googleapis/gstatic; keep everything inline/system.
