# Add decision records (/fodo:decide) and let other skills record decisions

## Request
Add decision records to fodo: a new /fodo:decide skill that writes decision files (context, options, choice, consequences, link to the originating item) into docs/todo/decisions/ with an index.md and D1, D2 IDs, plus a gotchas.md for one-line gotchas. Also a shared way for other fodo skills (add, plan, start, done, review) to record a decision in that folder when one is made during their work, e.g. done asks to record a decision when the Deviations subsection is non-empty, plan records choices made from clarifying questions. Touches fodo.sh (init/reindex, dir_for, resolve), the init/list/review skills, conventions.md, the session-start hook (one summary line), the dashboard (must tolerate the folder), and the plugin description/keywords so the skill triggers on "we decided", "record this decision", "note this gotcha".

## Analysis
Fodo tracks *what* is being done (items moving planned → plan → busy → done/skipped). It has no
place for *why* a choice was made or for the small "gotchas" learned along the way. Today those
facts end up in the `### Decisions taken` block of a PRP (`/fodo:plan`) or in the `### Deviations
from the spec` and `### Discoveries` subsections of a Result (`/fodo:done`), buried inside one
item. A lightweight ADR-style log in `docs/todo/decisions/` makes them findable, and lets the
session-start hook and `/fodo:review` surface them.

Decisions are not todo items: they are never moved, only appended (and at most superseded). So
they sit beside the lifecycle folders as a separate record kind. That keeps `fodo.sh move` and the
item ID scheme untouched; only `init`/`reindex` (create the folder, write its index) and
`resolve()` (`D<n>`) grow.

Design points:
- **Filename** `docs/todo/decisions/<yyyy-mm-dd>.<slug>.md` (no `<type>` segment, so it cannot be
  confused with an item). Frontmatter: `title`, `date`, `status: accepted | superseded`,
  `superseded_by` (filename, optional), `item` (originating item filename, optional), `recorded_by`
  (`decide | plan | done | …`). Body: Context, Options considered, Decision, Consequences.
- **Gotchas** are one-liners, not worth a file each: `docs/todo/decisions/gotchas.md`, one bullet
  per line with a date and optional file path. `/fodo:decide --gotcha <text>` or plain
  "/fodo:decide note this gotcha: …" appends.
- **Shared recording**: one `fodo.sh decide <title> [--item <file>] [--by <skill>]` subcommand that
  creates the file from a template and prints its path, plus `fodo.sh gotcha <text>`. Every skill
  calls the helper, never writes the folder by hand (same rule as the index files). A short
  `reference/decisions.md` (or a section in `conventions.md`) tells skills *when* to record one.
- **Hooks into existing skills**:
  - `plan`: after the clarifying rounds, each row of `### Decisions taken` that settles an
    architecture/library/data choice is offered as a decision record (one AskUserQuestion, multi-
    select, default = record the non-trivial ones). The PRP keeps its block and links the files.
  - `done`: when `### Deviations from the spec` is not "none", ask "record this as a decision?";
    discoveries that read like gotchas are offered for `gotchas.md`.
  - `add` and `start`: no question by default; only when the user's text itself states a
    decision ("we decided to …") record it and mention the file.
  - `review`: new pass over decisions: still valid / superseded / should become a test or a
    `REVIEW.md` rule; stale gotchas (file no longer exists) are flagged.
  - `show`: accepts `D<n>`. `list`: adds a one-line "N decisions, last: … (date)" footer.
- **Session start**: one extra line when `decisions/` has files: count + last title/date; when
  `gotchas.md` mentions a path that appears in `git diff --name-only`, print those gotchas.
- **Dashboard**: `index.php` reads only the fixed stage folders (line 6), so it already tolerates
  `decisions/`. Showing a decisions count per repo is optional, keep it out of scope unless cheap.
- **Triggering**: the skills post says the description is what the model scans, so the `decide`
  description and the plugin `description`/`keywords` need the phrases "we decided", "record this
  decision", "note this gotcha", "why did we".

Risks / open questions:
- `D<n>` IDs shift like the others (positional by filename). Fine for `show`; decisions should link
  each other by filename (`superseded_by`), never by ID.
- Should `decide` also live as a standalone marketplace entry? No: it needs the fodo helper and the
  `.current` item; keeping it inside fodo is the decided direction (see the request).
- Existing repos: `reindex` must create `decisions/` on the fly like it does for `someday/`.

## PRP

### Goal
`docs/todo/decisions/` holds the *why* beside the *what*: one markdown file per decision
(`<yyyy-mm-dd>.<slug>.md`, no type segment) with an `index.md` and positional IDs `D1, D2, …`, plus
`gotchas.md` with one dated line per gotcha. `fodo.sh decide` and `fodo.sh gotcha` are the only
writers. A new `/fodo:decide` skill records a decision or a gotcha on demand; `/fodo:plan` offers
its Decisions taken rows as records, `/fodo:done` asks when its Deviations are not "none" and offers
discoveries as gotchas, `/fodo:add` and `/fodo:start` record only an explicit "we decided …" in the
request text, `/fodo:review` walks the decisions, `/fodo:show D<n>` prints one, `/fodo:list` ends
with a decisions count line. The SessionStart hook prints a decisions summary line and the gotchas
whose path is in the current diff. The dashboard shows a decisions count per repo.

### Why
- Decisions and gotchas are the highest-signal context for the next agent, and today they are
  buried inside one item's PRP or Result section.
- A session that starts with "3 decisions, last: …" and the gotchas that touch the files being
  edited avoids re-deciding and re-discovering.
- It reuses fodo's shape (markdown in `docs/todo/`, helper-owned indexes, positional IDs, review
  pass, dashboard), so nothing new has to be learned.

### Decisions taken
- Where → **inside fodo** as `/fodo:decide` + `docs/todo/decisions/`, not a separate plugin (user, before planning)
- Recording from plan/done → **offer, user picks**: plan shows its Decisions taken as one multi-select
  AskUserQuestion (non-trivial rows preselected, naming/default rows not); done asks yes/no when
  Deviations ≠ "none" (user)
- Gotchas → **`decisions/gotchas.md`**, one dated bullet per line with an optional `path:` prefix;
  not in the index (user)
- SessionStart → **count line + diff-matched gotchas** (user)
- Scope extras → **review pass** and **dashboard count** are in; **supersede support**
  (`--supersedes D<n>`, struck-through index rows) is a follow-up todo. A `superseded_by:` field may
  be set by hand and is shown in the index when present, nothing more (user)
- Filename → `<yyyy-mm-dd>.<slug>.md`, two segments, so `cut -d. -f2` never yields a type; the
  slug is 2–6 hyphenated lowercase words from the title (default, Claude)
- Frontmatter → `title`, `date`, `status: accepted`, optional `item: <item filename>`,
  `recorded_by: decide|plan|done|add|start`, optional `superseded_by` (default, Claude)
- Body sections → `## Context`, `## Options considered`, `## Decision`, `## Consequences`; the
  helper writes the skeleton with the title and `## Decision` filled from its argument, the skill
  fills the rest by editing the file (same split as item files: helper = structure, skill = prose)
  (default, Claude)
- Gotcha line format → `- <yyyy-mm-dd> [path/to/file:] <text>`; the hook matches the `path:`
  prefix (up to the first `:`) as a substring of `git diff --name-only HEAD` plus untracked files
  from `git status --porcelain`; gotchas without a path never match (default, Claude)
- `D<n>` → positional by filename like the others, case-insensitive; never stored in a file (default, Claude)
- Hook independence → the decisions line prints even when `busy/` is empty or absent; nothing
  prints when `decisions/` has no files and no gotchas (default, Claude)
- Dashboard → count only: `N decisions` in the card totals (always, not behind `?all=1`) and in
  the repo detail header; no list, no stage column, no CSS token beyond the totals span (default, Claude)
- Review → after the stale-items rounds, one round per up to 4 decisions, oldest first: **Keep**
  (sets `reviewed`), **Superseded** (ask which decision or free text → `superseded_by`,
  `status: superseded`), **Make a rule/test** (queue `/fodo:add`); gotchas whose `path:` no longer
  exists are listed as "stale gotchas" for the user to delete by hand (default, Claude)
- `/fodo:decide` with no arguments lists `decisions/index.md` and the gotchas (default, Claude)

### Known gotchas & library quirks
- **`set -euo pipefail` + missing dir**: `write_index` redirects into `"$dir/index.md"`; `reindex` must
  `mkdir -p "$ROOT/decisions"` first, exactly like the someday line, or every command breaks in old repos.
- **usage() prints a fixed line range** of the header comment (`sed -n '5,20p'`); adding usage lines means
  widening the range, and `tests/fodo.bats` "unknown command exits 1, help exits 0" checks it still prints.
- **session-start.sh exits early** when `busy/` is missing or empty. Restructure: compute the decisions
  text first, print it, then the busy block with `exit 0` replaced by skipping. The existing hooks.bats
  "prints nothing when busy/ is empty" must still pass (no decisions in that fixture).
- **The hook has no git guarantee**: wrap `git diff --name-only HEAD` and `git status --porcelain` in
  `2>/dev/null || true`; a repo with no commits makes `HEAD` invalid, treat it as "no diff".
- **gotcha text safety**: the helper takes the text as `"$*"`, flattens newlines and trims like `wait_item`
  does; a leading `path/to/file:` is kept verbatim. Never `eval`.
- **Slug collisions**: `decide` must refuse (exit 1, "exists: …") when `<date>.<slug>.md` already exists,
  like `retype` does, instead of overwriting.
- **item_files() uses `20*.md`**: `gotchas.md` is therefore invisible to `nth`, `write_index` and the
  dashboard glob, which is what we want. Do not rename it to a date-prefixed name.
- **resolve `*.md` branch** uses `find "$ROOT" -name`, so `/fodo:show <decision filename>` already works.
- **dashboard items()** derives `type` from the second filename segment; decision files have a slug there.
  Count them with `glob`, never pass them through `items()`.
- **Escaping**: everything rendered from repo files goes through `e()`; the count is an int.
- **bats is 0.4.0 locally** (no `-f`): run whole files. `bats tests/` runs them all.
- **macOS BSD tools**: `sed -E`, `date -j`; no `grep -P`, no `readarray`. Mirror existing helpers.
- **Plugin cache vs working copy**: the running `/fodo:*` skills come from `~/.claude/plugins/cache/...`,
  not from `plugins/fodo/`. Test skills with `claude --plugin-dir plugins/fodo` after `/reload-plugins`.
- **Skill descriptions are what the model scans** to trigger; put the phrases in the `decide`
  description, not only in the body.

### Approach
Helper first, then the skill, then the hooks into the other skills, then hook/dashboard/docs.

**Helper (`fodo.sh`)**
- `decide <title> [--item <file>] [--by <skill>]`: slugify the title (lowercase, non-alnum → `-`,
  squeeze, trim, max 6 words), path `$ROOT/decisions/$(date +%F).<slug>.md`, refuse if it exists,
  write the skeleton (frontmatter `title`, `date`, `status: accepted`, `item:` when given,
  `recorded_by:` default `decide`; body `# <title>` + the four `## ` sections, each with a one-line
  placeholder in angle brackets, `## Decision` holding the title), `reindex`, print the path.
- `gotcha <text...>`: flatten/trim like `wait_item`; `mkdir -p $ROOT/decisions`; create
  `gotchas.md` with a `# Gotchas` heading on first use; append `- <date> <text>`; print the file path.
- `write_index` gets a `decisions` mode: `| ID | Date | Status | Item | Title | File |`, Status shows
  `superseded → <superseded_by>` when that field is set, Item shows the `item:` filename as a relative
  link (`../<folder>/<file>` is unknown at write time, so plain text is fine).
- `list` adds `_N decision(s) in decisions/ (/fodo:decide to list them)._` when N > 0.
- `resolve`: `D<n>`; `dir_for`: `decisions` (read-only target: `move_file` must NOT accept it; keep its
  `case` unchanged).

**Skill `/fodo:decide`** (`skills/decide/SKILL.md`), description with the trigger phrases
("we decided", "record this decision", "note this gotcha", "why did we", "ADR"):
- no args → `reindex`, print `decisions/index.md` and, if present, `gotchas.md`.
- `--gotcha <text>` or text starting with "gotcha:" → `fodo.sh gotcha <text>`; if the text names a
  file in the repo, put it first as `path:`.
- otherwise → title = the text's first clause; `fodo.sh decide "<title>" --item <current busy item
  filename if any> --by decide`; then fill Context / Options considered / Consequences from the
  conversation (ask one question only if the options are genuinely unknown); print the path and
  its `D<n>`.

**Hooks into other skills** (all go through the helper; `reference/decision_template.md` holds the
"when to record" table the skills point to):
- `plan` step 6, after the PRP is saved: one AskUserQuestion, multi-select, listing the Decisions
  taken rows (preselect those marked "(user)" or that pick an architecture/library/data model;
  deselect naming/defaults). For each selected row: `fodo.sh decide "<row title>" --item <file>
  --by plan`, fill Context (the question), Options (the alternatives offered), Decision, Consequences;
  append `(recorded: decisions/<file>)` to the row in the PRP.
- `done` step 3b, before the move: if Deviations ≠ "none", AskUserQuestion "Record this deviation as
  a decision?" (one question, Yes (Recommended)/No); on Yes one `decide` per deviation bullet,
  `--by done`. Then, for each Discovery that reads like a gotcha (a surprising fact about a file or
  tool), offer them in one multi-select; selected ones go to `fodo.sh gotcha` with the path.
- `add` and `start`: only when the request text contains an explicit decision ("we decided", "we
  will use X instead of Y", "decision:"), record it with `decide --by add|start` and mention the
  path; never ask.
- `review` step 5b: for each decision file (oldest first, 4 per round) Keep / Superseded / Make a
  rule or test; act as in Decisions taken. Then list gotchas whose `path:` no longer exists.
- `show`: `D<n>` accepted (the helper does the work). `list`, `init`: one-line mentions.

**SessionStart hook**: before the busy block, if `$ROOT/decisions` has `20*.md` files print
`Fodo: N decision(s) recorded in docs/todo/decisions/, last: <title> (<date>); /fodo:show D<n> prints one.`;
if `gotchas.md` exists, collect changed paths (`git diff --name-only HEAD`, untracked from
`git status --porcelain`), and print `Gotchas for files in your current diff:` followed by each
matching line. Print nothing of this when there is nothing.

**Dashboard**: per-repo `decisions` count in the block, a `N decisions` span in the card totals
(always) and the same in the repo detail header. Header comment updated.

**Docs**: conventions (layout, IDs, helper list, rule "only the helper writes decisions/"),
README (command row, paragraph after the waiting/review prose), plugin.json description
("…record decisions and gotchas…") and keywords (`decisions`, `adr`, `gotchas`). Do not bump the version.
