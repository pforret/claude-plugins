# Show task details in-page instead of the kanban tooltip

## Request
the mouseover details in each task in http://fodo.test/?repo=1 is ugly. if the user clicks on a task, go to http://fodo.test/?repo=1#B1 and print the task information in a clear format in the page

## Analysis
Changes existing behaviour of the repo detail page. `render_kanban()` in
`plugins/fodo/dashboard/index.php` builds each `article.kcard` with a plain-text `title=""` tooltip
(filename, request excerpt from `request_peek()`, created/planned/started/done dates, last activity,
waiting reason, next `/fodo:` command). The card title links to `file://…`, which browsers mostly
block from an http page, so a click does nothing useful today.

New behaviour: each card gets `id="B1"` (its positional ID) and the card links to `#B1`; the page
shows a detail panel for the targeted item with the same facts laid out clearly (ID, type, size,
confidence, dates, waiting, next command, file path) plus the item's content.

Open questions:
- **Panel mechanism**: render one hidden detail block per item and show it with CSS `:target`
  (no JS, works with the existing read-only page) vs. a small script that reads `location.hash`.
  `:target` is simpler; with many done items it renders more HTML, but done/skipped are capped at 10.
- **How much content**: just the metadata + Request, or render the whole markdown (Analysis, Plan,
  PRP…)? There is no markdown renderer in the dashboard today; showing the sections as escaped
  `<pre>` text, or a minimal heading/list renderer, are the cheap options.
- Keep a short tooltip (e.g. just the filename) or drop it entirely?
- IDs shift when items move, so `#B1` links are not permanent; acceptable for a live view, but an
  anchor on the filename would be stable. The request asks for `#B1`.
- The table view (`?view=table`) could link to the same anchors.

## Impacted files
- `plugins/fodo/dashboard/index.php` — `render_kanban()`: anchors/ids on cards, drop the long tooltip, render the detail panel(s); helper to read item sections
- `plugins/fodo/dashboard/style.css` — detail panel layout (definition list, sections), `:target` show/hide, all four color schemes, mobile
- `tests/web.bats` — card has `href="#B1"`/`id`, detail panel contains request and dates, content is escaped

## Plan
See the PRP blueprint below (decisions taken: side panel via CSS `:target`, metadata + all sections
rendered with a minimal markdown renderer, tooltip removed).

## Acceptance criteria
- Clicking a card on `?repo=<n>` navigates to `?repo=<n>#<ID>` (e.g. `#B1`) and shows that item's details in the page.
- Details show ID, title, type, size, confidence (if any), all stage dates, waiting reason (if any), next `/fodo:` command, filename, and every `##` section of the item body rendered as simple HTML (headings, lists, code, bold, links), all text HTML-escaped.
- No ID collisions: planned `#1`, done `#done-1`, skipped `#skipped-1`.
- Opening a URL with `#B1` directly shows the panel.
- The long tooltip is gone (no `title=` on `.kcard`).
- Readable in all four color schemes and on a phone-width screen.
- `bats tests/web.bats` passes.

## PRP

### Goal
On the repo detail page (`/?repo=<n>`, kanban view), every card links to `#<ID>` (e.g. `#B1`).
When the URL fragment matches an item, a sticky side panel to the right of the board shows that
item's metadata and its full markdown body rendered as clean HTML. No JavaScript; the multi-line
`title` tooltip on cards is removed.

### Why
- The tooltip is unreadable (plain text, no layout, truncated request) and invisible on touch devices.
- Card titles link to `file://…`, which browsers block from an http page, so clicking does nothing today.
- Lets the user read a whole item (Analysis, Plan, PRP) from the dashboard without opening an editor.

### Decisions taken
- Content → metadata + every `##` section, rendered by a tiny built-in markdown renderer (user).
- Placement → sticky side panel like the `/agents` peek card, stacked below the board on narrow screens; pure CSS `:target` (user).
- Tooltip → removed entirely (user).
- Anchor IDs → the card's visible positional ID for B/P/S and planned (`B1`, `P2`, `S1`, `3`); done/skipped (bare numbers too) get `done-<n>` / `skipped-<n>` to avoid colliding with planned (default, rationale: the kanban shows numeric IDs for three stages).
- Which panels are rendered → only for cards actually shown on the board (done/skipped capped at 10), so at most ~30 + backlog file reads per page load (default).
- Table view → unchanged (keeps its `file://` links); out of scope (default).
- No third-party markdown library: the dashboard is a single dependency-free PHP file (default).

### Known gotchas & library quirks
- Escape first, then add markup: run e() on each line/inline segment before turning `**x**`, `` `x` ``, `[t](u)` into tags. Link URLs: only allow `http(s)://` (else render text only) to avoid `javascript:` hrefs.
- Item bodies contain fenced code blocks (```yaml, ```bash) with `#` lines: inside a fence, nothing is parsed (no headings/lists).
- Skip the frontmatter (between the first two `---` lines) and the leading `# <title>` H1 (title is the panel heading). Render `##` as `<h4>`, `###` as `<h5>` inside the panel.
- Items can be large (PRPs): cap the read at e.g. 200 KB; the panel body scrolls (`max-height` + `overflow:auto`).
- HTML `id="1"` is valid; `:target` needs no selector escaping because CSS never names the id.
- The 60 s meta refresh reloads the same URL including the fragment, so the panel stays open; verify in a browser.
- The existing `.kcard` has `cursor:default`; the whole card should be clickable: make `a.title` the link (href="#ID") and stretch it with `::after { content:""; position:absolute; inset:0 }` on a `position:relative` card, or wrap — keep the title link as the single accessible link.
- Keep the positional ID logic identical to render_table() (comment at line ~384) so IDs match `/fodo:*` commands.
- Done/skipped panels: only for the cards rendered (the 10 newest).

### Anti-patterns
- Don't pull in a markdown library or JS; keep the single-file, dependency-free dashboard.
- Don't output any item text without e(); don't allow non-http(s) link targets.
- Don't render panels for done/skipped cards that are not shown.
- Don't change positional ID numbering.

### Discoveries

- Playwright `goto` to the same URL + fragment does not reload; a cache-busting query is needed when testing `:target` pages.
- Not verified: whether the 60 s `<meta http-equiv="refresh">` keeps the fragment in every browser (should, per spec of reloading the current URL).
- Table view still links to `file://…` (blocked from http pages); could link to the kanban anchors — possible follow-up.
