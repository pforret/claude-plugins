# Add someday/ state for parked items

## Request
GTD-inspired: a `someday/` state (GTD's "Someday/Maybe"), for ideas you don't want to lose but aren't
committing to. It keeps the planned list short and keeps `skipped/` for things you've actually rejected.
A review can move items back out of it.

## Analysis
Today an idea is either planned (cluttering the list) or skipped (reads as rejected). A new folder
`docs/todo/someday/` with its own index and an ID prefix (e.g. `S1`, `S2`) fits the existing layout.
Every place that enumerates stages must learn the new one: `dir_for`, `init`, `reindex`, `move`
targets, `path` ID parsing, the dashboard stage list and its CSS colors. Need a way back: moving
from someday to planned (`fodo.sh move S1 planned`), which `move` does not support today.

## Impacted files
- `plugins/fodo/scripts/fodo.sh`: new dir, index, `S<n>` IDs, `someday` and `planned` move targets
- `plugins/fodo/dashboard/index.php`: show someday items (probably behind the "show all" toggle)
- `plugins/fodo/dashboard/style.css`: stage color for someday
- `plugins/fodo/reference/conventions.md`: layout, lifecycle, ID table
- `plugins/fodo/skills/init/SKILL.md`, `skills/list/SKILL.md`: mention the new folder / table
- `plugins/fodo/skills/someday/SKILL.md`: new `/fodo:someday <id>` (park) command
- `plugins/fodo/README.md`: command table and lifecycle
- `tests/fodo.bats`: init, move, path, reindex and list tests for someday
- `tests/web.bats`: someday column with `?all=1`, hidden by default

## PRP

### Goal
A fifth lifecycle side-branch `docs/todo/someday/` (GTD "Someday/Maybe") with its own `index.md` and IDs `S1, S2, …`.
`/fodo:someday <n|Pn> [note]` parks a backlog or plan item, `/fodo:someday` lists the parked items, and
`/fodo:someday S<n> back` returns one to the backlog. The helper supports it everywhere: init, reindex (also on old
repos without the folder), `path S<n>`, `move … someday`, `move S<n> planned`. `/fodo:list` ends with a one-line count.
The dashboard shows someday items only in the "show all" view (`?all=1`), as a Someday column/table, distinct from skipped.

### Why
- Ideas you don't commit to stop cluttering the backlog, and `skipped/` keeps meaning "rejected".
- A review (planned `/fodo:review`) can bring parked items back with one command.
- It fits the existing folder-per-stage design with positional prefixed IDs.

### Decisions taken
- Commands → **one new skill `/fodo:someday`**: `<id> [note]` parks, no args lists, `S<n> back` un-parks. (user)
- Parkable → **planned (`n`) and plan (`Pn`) items only**. Busy/done/skipped are refused. A parked plan item keeps its
  PRP and `confidence`; "back" always returns it to the backlog (`docs/todo/`), where `/fodo:start` can still follow the PRP. (user)
- Dashboard → **only with `?all=1`**, like done/skipped. The button becomes "Show someday / done / skipped" /
  "Hide someday / done / skipped", and the top-bar count appears only then (it iterates `$stages`). (user)
- `/fodo:list` → **one count line** after the tables when someday has items:
  `_N item(s) in someday/ (/fodo:someday to list them)._`. (user)
- ID prefix → `S` (`S1`), case-insensitive like `P`/`B`. (default, Claude)
- Frontmatter → parking sets `status: someday` + `someday_at: <date>` (via move_file's `${target}_at`). Back sets
  `status: planned` and writes **no** date field: there's no `planned_at`, and it would be confused with `plan_at`.
  `someday_at` stays as history. (default, Claude)
- Note → optional free text after the id. When given, append `## Someday\n\n<note>` before moving. No reason is asked
  for (unlike skip), because parking should be low-friction. (default, Claude)
- Helper guards → `move … someday` only from `docs/todo/` or `plan/`; `move … planned` only from `someday/`. Other
  moves keep working as now. (default, Claude)
- Kanban position → Someday is the **leftmost** column (before Backlog) with `?all=1`: parked ideas sit beside the
  backlog, and the flow still reads left → right. The table view lists Someday after Backlog. (default, Claude)
- Colour → derived token `--someday: var(--type-change)` (violet in colour schemes, grey in mono), distinct from `--skipped` (orange). (default, Claude)
- Overview grouping → a repo whose only items are someday ones counts as "empty" (behind "Show N empty repos"). No change. (default, Claude)

### Known gotchas & library quirks
- **Old repos:** `reindex` writes `"$dir/index.md"` for every stage. Without `someday/` the redirect fails under
  `set -e` and breaks every command. `reindex` must `mkdir -p "$ROOT/someday"` before writing (so does `init`). Test it.
- `move_file` sets `${target}_at`. For `planned`, skip that (`[ "$target" = planned ] || set_field …_at`), and the
  destination dir is `$ROOT` itself (use `dir_for`).
- Guards in `move_file` need the source stage: `src=$(basename "$(dirname "$f")")`, which is `todo` (or the ROOT dir's
  basename) for the backlog. Compare the dir path to `$ROOT` / `$ROOT/plan` instead of basenames to be safe.
- `resolve`'s `*.md` branch uses `find "$ROOT"`, so it already finds files in someday/. No change needed there.
- `.current` only concerns busy. Moving to someday from plan/planned never touches it.
- `/fodo:start Pn` when the PRP item is back in the backlog: the start skill already follows a `## PRP` section if
  present, whatever the folder. Mention this in the someday skill's "back" step.
- Dashboard: `$stages` drives the top-bar counts and `$totals`, so adding `someday` under `$showAll` is enough for the
  counts. `render_kanban` uses its own order array; include 'someday' first. The detail table loop at :1052 has its own order too.
- Escape everything with `e()`. The new label/prefix strings are constants, but item data isn't.
- bats is 0.4.0 locally (no `-f`). Run whole files.

- Don't park busy items. Point the user to skip or (later) waiting_on.
- Don't show someday in the default dashboard view.
