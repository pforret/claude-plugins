fodo cheatsheet · per-repo todos, PRPs and decisions as markdown in docs/todo/

/plugin marketplace add pforret/claude-plugins · /plugin install fodo@pforret-claude

Happy path

/fodo:add <text>bug · change · feature, sized from the code
→
/fodo:plan 1research + questions until 9/10 → PRP; becomes P1
→
/fodo:start P1implement the PRP, run its validation loop; becomes B1
→
/fodo:doneverify the acceptance criteria, write the Result, archive
→
/fodo:commitmessage, semver bump, CHANGELOG, tag; you push

Small, clear items skip the plan: /fodo:start 1. Every week: /fodo:review. Blocked? /fodo:wait B1 <reason>. Not now? /fodo:someday 3. Never? /fodo:skip 3. Why did we…? /fodo:decide.

Day to day (this repo)

/fodo:add [--quick] <text>add an item, sized from the code; --quick: capture now, clarify later
/fodo:listbacklog (1, 2, …) plus the plan (P) and busy (B) tables
/fodo:show [id]print an item, or a decision (D2)
/fodo:plan <n>research, ask, write a PRP; moves to plan/
/fodo:start <n|Pn>implement (PRP if present); moves to busy/; resumes a waiting item
/fodo:done [Bn]verify criteria, append Result, move to done/
/fodo:skip [id]drop with a reason; move to skipped/
/fodo:someday [id [note] | Sn back]park an idea, list parked ones, bring one back
/fodo:wait [Bn] <reason> | resumemark a busy item as waiting for something, or clear it
/fodo:decide [<text> | --gotcha <text>]record a decision (small ADR, D1…) or a gotcha; no args: list them
/fodo:review [planned-days [busy-days]]weekly review of stale items (30 / 14 days): keep, re-plan, park, skip, start
/fodo:busyin progress and planned, with what items wait on
/fodo:commit [<message>]stage all, generated subject, bump estimate like setver (! major · feat minor · else patch · bookkeeping none), ask once, write VERSION.md, composer/package.json, .env.example, plugin.json, update CHANGELOG.md, commit, tag vX.Y.Z; never pushes

IDs

1, 2backlog, docs/todo/
P1planned with a PRP, plan/
B1busy, busy/ (⏸ when waiting)
S1someday, someday/
D1decision, decisions/ (never moved)
(empty)the item you started last

IDs are positions in a table and shift when items move: re-list after a move. A filename always works too.

Layout

docs/todo/
  index.md + 2026-10-30.feature.slug.md   backlog
  plan/      PRP written, waiting to start
  busy/      in progress   (.current = last started)
  done/  skipped/  someday/
  decisions/ one ADR per file + gotchas.md

Item = one markdown file: Request · Analysis · Impacted files · Plan · Acceptance criteria · PRP · Result. Filenames never change, only the folder. Legend: 🐞 bug 🔧 change ✨ feature · 🟢 small 🟡 medium 🔴 large ❔ unsized.

All repos

/fodo:busy --allbusy and plan tables of every registered repo
/fodo:repos [prune]the registry (~/.claude/todo/repos.csv); prune drops gone repos

Terminal, after /fodo:cli

fodo list · fodo busy [--all]the same tables, no Claude needed
fodo pickchoose an item (fzf) and open Claude Code on it
fodo path <id> · fodo currentresolve an ID to its file
fodo move <id> <stage>plan · busy · done · skipped · someday · planned
fodo set|unset <file> <key> [v]frontmatter field, then reindex
fodo wait|resume <file> [reason]waiting marker
fodo decide <title> · fodo gotcha <text>write a decision skeleton · append a gotcha
fodo stale · fodo reindex · fodo reposstale table · rebuild indexes · registry
semver.sh current|next|files|set|tagthe version helper behind /fodo:commit

Rules of the game

Never hand-editindex.md, .current, files in decisions/ (use the helper)
Never deleteditems end in done/ or skipped/
Gitonly /fodo:commit commits and tags; nothing pushes
Session starta hook lists the busy items and gotchas for the files you touch
