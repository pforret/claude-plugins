fodo cheatsheet · per-repo todos, PRPs and decisions as markdown in docs/todo/

Claude Code plugin · GTD for repos · github.com/pforret/claude-plugins · MIT

1 · Install once

  1. Marketplace /plugin marketplace add pforret/claude-plugins
  2. Plugin /plugin install fodo@pforret-claude
    updates: /plugin marketplace update pforret-claude, or turn on auto-update
  3. Dashboard /fodo:web starts it on 127.0.0.1:7787 (PHP 8.1+; stop · status · <port>)
    and/or /fodo:valet serves it permanently as http://fodo.test with Laravel Valet (macOS, no sudo)
  4. Terminal /fodo:cli puts a fodo command on your PATH (asks which directory; never sudo)
    then fodo list, fodo busy --all, fodo pick work in any terminal
  5. Look on the dashboard open /config: header font, body font and color scheme
    Light Colors (default) · Light Monochrome · Dark Colors · Dark Monochrome, saved in ~/.claude/todo/config.json
  6. Per repo /fodo:init creates docs/todo/ with its folders
    optional: the first other /fodo: command in a repo does it too

2 · Happy path

  • /fodo:add fix the login redirectbug · change · feature, sized from the code; a trivial item is offered right away (two-minute rule)
  • /fodo:plan 1research + clarifying questions until 9/10 confidence → PRP; the item becomes P1
  • /fodo:start P1implement the PRP, run its validation loop; the item becomes B1
  • /fodo:doneverify every acceptance criterion, write the Result, archive to done/
  • /fodo:commitgenerated message, semver bump, CHANGELOG, tag vX.Y.Z; you push

Small, clear items skip the plan: /fodo:start 1. Blocked? /fodo:wait B1 <reason>. Not now? /fodo:someday 3. Never? /fodo:skip 3. Once a week: /fodo:review. Lost? /fodo:help. Everything is markdown in docs/todo/.

3 · Items · this repo

/fodo:add [--quick] <text>add an item, sized from the code; --quick or several lines: capture now, clarify later
/fodo:listbacklog (1, 2, …) plus the plan (P) and busy (B) tables
/fodo:show [id]print an item, or a decision (D2)
/fodo:plan <n>research, ask, write a PRP; moves to plan/
/fodo:start <n|Pn>implement (PRP if present); moves to busy/; resumes a waiting item
/fodo:done [Bn]verify criteria, append the Result, move to done/
/fodo:skip [id]drop with a reason; move to skipped/
/fodo:someday [id [note] | Sn back]park an idea, list parked ones, bring one back
/fodo:wait [Bn] <reason> | resumemark a busy item as waiting for something, or clear it
/fodo:busy [--all]in progress and planned, here or in every registered repo

4 · Memory, review, git

/fodo:decide <text>record a decision as a small ADR in decisions/ (D1…)
/fodo:decide --gotcha <text>one-line gotcha in gotchas.md; start with path/to/file: to tie it to a file
/fodo:decidelist decisions and gotchas
/fodo:review [planned-days [busy-days]]weekly review of stale items (backlog 30 days, busy 14, PRPs whose files changed): keep, re-plan, park, skip, start
/fodo:repos [prune]the registry of repos; prune drops the gone ones
/fodo:commit [<message>]stage all, generated subject (or yours), bump estimate like setver (! major · feat minor · else patch · bookkeeping none), ask once, write the version into VERSION.md, composer/package.json, .env.example, plugin.json, update CHANGELOG.md, commit, tag vX.Y.Z; never pushes

5 · Layout, IDs and rules

docs/todo/
  index.md + 2026-10-30.feature.slug.md   backlog
  plan/   busy/ (.current = last started)
  done/   skipped/   someday/
  decisions/  one ADR per file + gotchas.md

IDs

1, 2backlogS1someday
P1planned with a PRPD1decision (never moved)
B1busy (⏸ waiting)emptythe item you started last

IDs are table positions and shift when items move: re-list after a move; a filename always works. One file per item (Request · Analysis · Impacted files · Plan · Acceptance criteria · PRP · Result); only its folder changes.

Rules

Never hand-edit index.md, .current or decisions/ (the helper writes them) · items are never deleted, they end in done/ or skipped/ · only /fodo:commit commits and tags, nothing in fodo pushes · a SessionStart hook lists the busy items and the gotchas for the files you touch.

6 · Terminal · after /fodo:cli

fodo list · fodo busy [--all]the same tables, no Claude needed
fodo pickchoose an item (fzf) and open Claude Code on it
fodo path <id> · fodo currentresolve an ID to its file
fodo move <id> <stage>plan · busy · done · skipped · someday · planned
fodo set|unset <file> <key> [v]frontmatter field, then reindex
fodo wait|resume <file> [reason]waiting marker
fodo decide <title> · fodo gotcha <text>decision skeleton · append a gotcha
fodo stale · fodo reindex · fodo reposstale table · rebuild indexes · registry
semver.sh current|next|files|set|tagthe version helper behind /fodo:commit

In a repo without docs/todo/, run fodo init first.
